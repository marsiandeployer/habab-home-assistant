# Помощник для подключения устройств

Исходники описывают кандидат Habab Home 0.3.4; опубликованный Windows-архив пока остаётся на стабильной версии 0.3.1. Один административный чат автоматически открывается после авторизованной загрузки Home Assistant на любой странице. На компьютере это немодальная панель справа; на телефоне сверху остаётся дашборд, снизу открывается чат. Его можно свернуть или раскрыть на весь экран. Кнопки и WebSocket-команды доступны только администраторам; кнопка на странице AI открывает тот же чат. Публичные обычная и preview-страницы используют одну реализацию чата и общий prompt. Публичное демо отвечает через DeepSeek без инструментов, приватного Core и устройств.

Помощник выполняет команды от root внутри контейнера Home Assistant. Он может проверять конфигурацию, писать файлы в `/config`, запускать доступные в образе программы и диагностировать подключения. Включение и сканирование Bluetooth требуют отдельного доступа к BlueZ хоста.

Подключите провайдера в разделе **AI**: успешное действие «Проверить и сохранить» выбирает его для веб-чата и Telegram. OpenAI и DeepSeek используют собственные API напрямую. Habab использует сервер Habab и отдельный ключ доступа, который выдаёт администратор сервиса; ключ OpenAI в поле Habab не подходит. Новые подключения не удаляют сохранённые подключения других провайдеров. Серверная настройка Habab и реальный голос требуют отдельной проверки; одно появление вкладки Habab не подтверждает их работу.

OpenCode работает внутри контейнера Home Assistant от root; настройки, ключи и история OpenCode хоста не подключаются. Команда `habab-ha` даёт активной веб- или Telegram-задаче доступ к штатным действиям Home Assistant. Backend проверяет администратора и владельца flow; секреты и значения форм не попадают в ответ.

Веб и Telegram проходят через общий `AssistantService` и один локальный OpenCode runtime с рабочей папкой `/config/.habab-opencode/workspace`; их сессии и истории разделены. Веб-контекст принадлежит администратору HA; Telegram-контекст привязан к администратору, записи бота и личному чату. Хранилища `habab_home.agent_sessions` и `habab_home.telegram_sessions` сохраняют прежние ключи сессий. Нативные Assist entries используют тот же сервис и подключение провайдера через ограниченный адаптер: модель получает только инструменты, открытые конфигурацией Assist, без OpenCode и root.

Настройка интеграции остаётся в том же веб-чате. Карточка использует native `step-flow-form` и context host с `contextMixin` из полного frontend для Core 2026.10.2 (`20260930.4+habab.7`). Home Assistant сохраняет штатные callbacks полей, selectors, переводы и проверки required/hidden/read-only. Модель получает `input_fields` только с именами, типами и обязательностью полей; defaults, варианты, подписи, введённые значения и URL не передаются. Ввод формы отправляется напрямую через owner-scoped `habab_home/setup/*` WebSocket-команды и не попадает в чат, историю, Telegram или логи. После загрузки нового шага чат показывает форму, если пользователь читает конец переписки; при просмотре старых сообщений появляется кнопка «Открыть форму настройки». Фокус остаётся на текущем элементе. Для пароля, OAuth и других защищённых шагов Telegram направляет владельца в веб-интерфейс.

## Подключение Telegram

Войдите администратором и откройте раздел **Telegram** в боковом меню Home Assistant.

1. Создайте бота через `@BotFather`, вставьте его токен и нажмите «Подключить бота». Home Assistant сохраняет токен в config entry; токен не возвращается в интерфейс и очищается из поля после ухода со страницы.
2. Нажмите «Получить ссылку для привязки» и откройте одноразовую ссылку в личном чате с ботом. Это личный доступ владельца; он сохраняется отдельно от домашней группы.
3. Создайте группу «Моя дача» или «Моя квартира», добавьте бота и доверенных людей. В разделе Telegram нажмите «Создать ссылку для группы», откройте одноразовую Telegram-ссылку `startgroup` и выберите созданную группу. Назначьте бота администратором: это нужно для проверки членства.

Каждый участник открывает личный чат с ботом и нажимает «Запустить». Бот проверяет членство при каждом обращении и не обрабатывает сообщения, отправленные в саму группу. Если участник покинет группу, его следующий запрос будет отклонён. Пользователь без доступа получит от бота подсказку. Команда `/new` начинает отдельный диалог, `/cancel` останавливает текущую задачу. Отвязка только группы сохраняет личную привязку владельца; отключение бота отзывает обе привязки. Для OAuth, пароля, кода подтверждения или карточки установки откройте веб-чат HA; не отправляйте секреты боту.

## Xiaomi Home из чата

Попросите: «Подключи Xiaomi Home в России». Помощник вызывает штатное действие
`habab-ha '{"action":"xiaomi_setup"}'` и показывает карточку внутри чата.
Она устанавливает проверенную официальную интеграцию после согласия владельца,
предлагает разрешить перезапуск Home Assistant, открывает OAuth и импортирует
устройства. При нескольких домах владелец выбирает нужные; один дом выбирается
автоматически. В конце помощник проверяет интеграцию и устройства командами.

В карточке Xiaomi нажмите «Показать пылесос на главной», чтобы добавить найденные в
реестре видимые пылесосы в избранное нативного Home. Если Home Assistant
зарегистрировал для такого же устройства сенсор заряда, карточка добавит и его.
Пользовательские избранные и другие настройки главной сохраняются. Действие
открывает Home overview, не создаёт отдельную Lovelace-панель и не меняет
настройку панели по умолчанию. Чат остаётся открыт; на телефоне он возвращается
к нижней половине экрана. Пылесосный tile показывает штатные команды запуска или
паузы, остановки и возврата на базу, если сущность их поддерживает. Избранные сущности
отображаются и без `usage_prediction`.

Пароль и код подтверждения остаются на сайте Xiaomi. Если Windows не открывает
`homeassistant.local`, адрес страницы после входа можно передать через защищённое
поле карточки. Backend проверяет зарегистрированный callback и OAuth state,
затем передаёт результат только соответствующему native webhook. Произвольные
HTTP-запросы не выполняются. Адрес и код не входят в AI-сообщения или Store карточки.

Установка и перезапуск требуют отдельных нажатий в карточке. Сценарий не меняет
настройки Windows и не требует специального Xiaomi BAT. Компонент Xiaomi
скачивается для личного некоммерческого использования и не включён в архив Habab.
В сборке включён штатный `webhook`, необходимый для возврата Xiaomi после входа.

Если настройка Xiaomi уже начата в вебе, явный запрос из доверенного Telegram-диалога может привязать уведомление к этому диалогу, пока у карточки нет другого исходного Telegram-диалога. Текущий OAuth, выбранный дом и владелец карточки сохраняются. Участник домашней группы получает результат в личку только после повторной проверки членства; в группу результат не отправляется.

Состояние карточки хранится в приватном Store Home Assistant по ID администратора.
Другой администратор не получает ссылку или код этого подключения. После
перезапуска карточка возобновляет установку, а незавершённый OAuth начинает заново.
Успешное создание config entry ещё не считается загрузкой: карточка ждёт `loaded`.

## Запуск без второй установки OpenCode

Используется существующий нативный бинарник OpenCode для Linux musl. Node-обёртка и бинарник glibc для Alpine не подходят. Скрипт находит musl-вариант уже установленного npm-пакета, проверяет запуск в образе HA и сохраняет путь с SHA-256. Он ничего не скачивает и не копирует.

Из `habab/distribution/`:

```sh
docker compose -f compose.yaml build homeassistant
python3 prepare-opencode.py --image habab-home:0.3.4
docker compose --env-file .env.opencode -f compose.yaml -f compose.opencode.yaml up -d homeassistant
```

Если пакет находится в другом месте:

```sh
python3 prepare-opencode.py --binary /absolute/path/to/musl/opencode --image habab-home:0.3.4
```

Откройте Home Assistant, войдите администратором и подключите DeepSeek в разделе **AI**. Чат появится после авторизованной загрузки; можно попросить: «Проверь, какие устройства обнаружил Home Assistant».

Проверена версия OpenCode **1.14.21**. После обновления файла повторите `prepare-opencode.py` и пересоздайте контейнер. Несовпадение SHA-256 блокирует запуск помощника.

Для упаковщика Android/PRoot предусмотрен явный параметр процесса Home Assistant
`HABAB_RUNTIME_KIND=android_proot`. Он передаёт общему помощнику сведения о
PRoot и sandbox Android. UID 0 гостевой системы не даёт root Android или доступа
к Bluetooth/Wi-Fi телефона. Без параметра используется прежний контекст Docker;
неизвестное значение блокирует запуск. Смена типа среды пересоздаёт приватный
процесс OpenCode. Провайдер, инструменты HA и разделение историй остаются общими.
Упаковщик должен передать этот параметр дочернему процессу HA. Unit-тесты контекста
не доказывают работу модели, Telegram или оборудования на физическом телефоне.

## Подключение Telegram через прокси

В разделе **Telegram** укажите токен собственного бота. Если Telegram недоступен
из вашей сети, заполните необязательное поле прокси: `http://host:port` или
`https://user:password@host:port`. SOCKS в этом поле пока не поддерживается.
Прокси используется при проверке токена, получении сообщений и отправке ответов.
При его отказе бот сообщает об ошибке без переключения на прямое соединение.
Чтобы убрать прокси, повторно подключите бота с пустым полем прокси.
Адрес с паролем хранится в настройках интеграции Home Assistant и после сохранения
не возвращается в браузер. Эти изменения нужно включить в сборку домашней установки;
ранее выпущенный Windows ZIP не обновляется автоматически.

## Что разделяется через volume

| Объект | Доступ |
|---|---|
| Один исполняемый файл OpenCode | Read-only bind mount в `/opt/habab-opencode/opencode` |
| Настройки, ключ DeepSeek и история host OpenCode | Не монтируются |
| HOME, кэш и история помощника | Отдельные каталоги `/config/.habab-opencode/`, права `0700` |
| HTTP API OpenCode | `127.0.0.1:4197` внутри контейнера, случайный пароль, без опубликованного порта |
| Браузер | Только авторизованный WebSocket API Home Assistant; ключи и пароль OpenCode не передаются |
| Веб-диалоги | Отдельная сессия для каждого пользователя HA; другой администратор не может открыть или остановить её через API |
| Telegram-диалоги | Отдельные сессии для владельца, записи бота и привязанного личного чата |
| Docker socket и корень хоста | Не монтируются |

Процесс OpenCode отделён от установленного на хосте OpenCode; сам файл программы передаётся контейнеру только для чтения. Веб и Telegram работают через один процесс и его настройки DeepSeek, а отдельные сессии разделяют историю. Ограничение сессий не закрывает `/config` от администратора, которому разрешены команды от root внутри контейнера.

Публичное демо позволяет переписываться с DeepSeek и получать инструкции. Его отдельный Flask API хранит последние сообщения в PostgreSQL под анонимной подписанной сессией. Ключ хранится только на сервере, запросы ограничены шестью в минуту на сессию и общим лимитом 200 в час. Сообщения удаляются после семи дней без активности. Этот чат не получает root, инструменты, доступ к приватному Core или реальным устройствам. Выполнение команд доступно в домашнем OpenCode-чате после входа администратором.

## Bluetooth

Команда `discover_devices` наблюдает от 1 до 15 секунд за результатами штатных zeroconf, SSDP и DHCP обнаружений Home Assistant и за его Bluetooth-сканерами. Список может быть неполным. Эта команда не сканирует Wi-Fi SSID, не проверяет доступность multicast и не меняет сеть. Новый discovery flow нужно явно принять до прохождения его шагов. Bluetooth-адаптер Windows не передаётся в Linux-контейнер Docker Desktop; этот путь не доказывает работу Bluetooth на Windows.

Для Windows Docker Desktop простой Bluetooth override не добавляет адаптер Windows или системный D-Bus. Для BLE можно использовать сетевой ESPHome proxy; шаги и границы USB/IP описаны в [инструкции Windows](../distribution/README-WINDOWS.md#bluetooth-на-windows).

Для Bluetooth на Linux-хосте должны работать BlueZ и системный D-Bus, а адаптер должен быть доступен хосту. Подключите override:

```sh
docker compose --env-file .env.opencode -f compose.yaml -f compose.opencode.yaml -f compose.bluetooth.yaml up -d homeassistant
```

Override передаёт `/run/dbus` и добавляет `NET_ADMIN`/`NET_RAW`, как описано в [документации Home Assistant Bluetooth](https://www.home-assistant.io/integrations/bluetooth/). Это разрешение на работу с Bluetooth хоста через его сервис. Read-only mount сокета не делает команды D-Bus доступными только для чтения. `privileged`, Docker socket и корень хоста для этого не нужны.

После подключения можно попросить: «Проверь адаптер, включи Bluetooth и запусти поиск на 10 секунд». Если адаптера, BlueZ или разрешений нет, помощник должен сообщить об ошибке. Обнаруженное устройство ещё нужно подключить через подходящую интеграцию Home Assistant; сканирование не выполняет сопряжение.

На текущей VM физическое Bluetooth-подключение не подтверждено. Проверка `bluetoothctl list` в отдельном контейнере с D-Bus завершилась ошибкой клиента D-Bus. Изменения BlueZ на хосте не выполнялись.

## Остановка и ошибки

Кнопка «Остановить» вызывает abort OpenCode. Уже выполненные изменения могут сохраниться. При истечении 180 секунд backend останавливает запрос и возвращает ошибку. Одновременно выполняется одна задача; второй запрос получает `busy`. Закрытие окна чата не останавливает задачу. История сохраняется, новый чат создаёт отдельный диалог.

При выходе Home Assistant процесс OpenCode и его группа завершаются. Автообновление, внешние плагины и MCP отключены. В интерфейс передаются сообщения пользователя и итоговый текст; внутренние рассуждения и сырые результаты инструментов исключены. Ответы фильтруются по известным ключам провайдеров и паролю runtime.

CLI `habab-ha` использует отдельный случайный capability-токен через loopback HTTP. Он работает только во время активной задачи администратора и не выдаёт браузеру постоянный токен HA. Конфигурационные flows привязаны к пользователю; стандартные сервисы выполняются с его контекстом. Для действий, требующих OAuth, пароля или нажатия кнопки на устройстве, помощник направляет владельца в интерфейс Home Assistant.

## Проверки и ограничения

Release check принятого образа 0.3.0 без source overlays зафиксировал 100 Python tests,
26 JavaScript tests, 10 native frontend tests, lint, pre/post-build typechecks и
полную frontend сборку. В изолированном Linux browser QA прошли 7/7 сценариев,
ошибок страницы не было. Native форма Time & Date создала загруженную сущность
реального времени, состояние проверили в Home Assistant; selector context matrix
проверен на синтетических данных без отправки формы. После исправления старта
bootstrap не дал ошибок и не обращался к Recorder при отключённой интеграции;
конфигурацию для теста не меняли. Это проверки принятого образа 0.3.0. Отчёты
находятся в `habab/qa/canonical-assistant/`:
`release-check.json`, `browser-result.json`, `bootstrap-after-fix.json` и
`form-lifecycle.json`.

Чистая сборка Docker-образа 0.3.1 на Core 2026.10.2 и Node 24.22.1 прошла;
digest: `9efca5c859862be84723b9ce299df0b41be43377e2b9e1c3a53c7699645fe8d1`.
В baked Linux QA прошли 105 Python tests, 30 host JavaScript tests, 8/8 JS
lifecycle tests под Node из образа и 5/5 transport tests под baked SDK. Отдельно
5/5 Telegram backend tests прошли под Python образа. Браузерная проверка baked
образа прошла 7 сценариев со статусом `PASS_WITH_LIMITS`, без ошибок страницы и
без source overlays. Проверены `/config/dashboard`, `/habab-ai`, `/lovelace/0`,
мобильный split, раскрытие и возврат. Публичные страницы и preview прошли ещё 7
сценариев. Высота viewport эмулировала место под экранную клавиатуру; физические
Windows и Android-устройства не проверялись. Запросов к провайдерам и сообщений
боту во время тестов не было. Отчёты находятся в `habab/qa/shared-assistant/`.

Отдельный model benchmark завершился `PASS_WITH_LIMITS` для семи запросов.
HA отклонил пустой запрос продолжения формы кодом 400; запись интеграции не
создалась. В benchmark форму не отправляли и команды управления устройствами не
выполняли. Отчёт: `habab/qa/canonical-assistant/model-benchmark-final.json`.

На Windows 0.3.0 помощник ответил на запрос без изменения настроек и устройств;
ответ совпал с реестром Home Assistant. В более ранней версии 0.2.0 наблюдался
`model_error`, причина которого не установлена. Кандидат 0.3.4 на Windows пока
не проверен. [Последняя успешная проверка Windows](../qa/cross-channel-setup/windows-assistant.json).

На физическом P30 проверена цепочка Telegram → защищённая штатная форма
Local To-do в веб-чате → загруженная интеграция и пустая сущность → уведомление
в исходном Telegram-чате. Использовался временный тестовый сетевой канал;
после проверки бот отключён и канал закрыт. Истории веба и Telegram разделены,
общими остаются сервис помощника и состояние настройки. Подключение Xiaomi
этим тестом не проверялось. [Отчёт P30](../android/qa/voice/habab-0.3.3-phone.json).

`discover_devices` возвращает ограниченные наблюдения из штатных источников Home Assistant, включая zeroconf, SSDP, DHCP и доступные Bluetooth-сканеры. Это не сканирование Wi-Fi и не доказательство BLE-доступа Docker Desktop к адаптеру Windows. BLE, реальный Telegram и физическое подключение устройств отмечаются как проверенные только после соответствующих сквозных тестов.

```sh
docker build -t habab-home:0.3.4 habab/distribution
docker run --rm --network none --entrypoint python3 -v "$PWD/habab/distribution:/diagnostics:ro" habab-home:0.3.4 -m unittest discover -s /diagnostics/tests -v
```
