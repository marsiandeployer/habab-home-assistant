# Habab Home 0.2.0 — проверка выпуска

Проверено 23 октября 2026 года в отдельном Linux Docker Home Assistant на loopback-порту 8402. Приватный owner-test этим прогоном не менялся. После появления support-туннеля дополнительно проверена установленная версия Windows; её настройки не менялись.

- 56 Python-тестов в итоговом образе: PASS.
- 7 тестов frontend lifecycle и dashboard: PASS.
- 5 Node transport-тестов с подменённым Bot API: PASS. Это не проверка живого бота.
- 5 контрактных тестов Windows callback: PASS. PowerShell и Windows UAC здесь не запускались.
- Native Chromium: нижняя правая кнопка, desktop nonmodal, сохранение черновика при переходе в настройки, Telegram sidebar, реальный ответ DeepSeek с карточкой Xiaomi, mobile fullscreen: PASS (`browser-result.json`).
- Public Chromium desktop/mobile: Telegram sidebar с инструкцией, отсутствие токена и Telegram API, нижний чат и доступность фонового меню при закрытом чате: PASS (`public-browser-result.json`).
- Пять свежих запросов к реальной модели проверены по инструментам OpenCode: безопасная подготовка Xiaomi, discovery, неизвестное устройство, обработка запроса секретов, запись/чтение/резервная копия/сравнение/удаление двух контрольных файлов: PASS (`model-result.json`). Компонент Xiaomi не устанавливался; OAuth и команды физическим устройствам не выполнялись.
- Runtime и исходники обоих native-компонентов и транспорта совпадают; версия 0.2.0, контейнер работает без повторных запусков (`build-identity.json`).
- Новый Windows ZIP содержит только 61 файл из allowlist. Публичная копия проверена по SHA-256. Gitleaks исходников и распакованного ZIP: PASS.

Ревью выявило перехват касаний полноэкранным host закрытого чата и молчаливую потерю Telegram-сообщения при заполненной очереди. Host больше не перехватывает фоновые события; авторизованный отправитель получает явный ответ при переполнении очереди. Для второго случая добавлен тест прав доступа и ответа.

Дополнительный native mobile прогон подтвердил касание фонового поля, открытие и закрытие штатного меню HA и повторное открытие чата. Общая оценка этого прогона PARTIAL: до взаимодействий зафиксирована одна ошибка Core WebSocket без известного кода; число ошибок не изменилось во время сценария. Причина и связь с расширением не установлены (`native-mobile-interaction.json`).

## Что остаётся проверить

Windows: живой туннель и native-вход подтверждены. Установленная версия — 0.1.0; её frontend точно совпадает с коммитом 3fb587549. В браузере кнопка находится в верхней панели, чат открывается, ввод и реальный ответ DeepSeek работают. Прямой WebSocket подтвердил семь загруженных интеграций, три служебных устройства и отсутствие vacuum-сущностей. Для новой версии 0.2.0 ещё нужен запуск обновлённого BAT владельцем и проверка кнопки справа внизу. Подробности без персональных данных — `windows-before-update.json`.

Telegram: отдельный бот, ввод токена в защищённом разделе HA, одноразовая привязка владельца, реальное сообщение и действие. Использование чужого работающего бота не проверялось и не выполнялось.

Xiaomi: официальный OAuth и реальное устройство на Windows, затем страница «Мои устройства». Dashboard проверен на идемпотентность и неизвестные значения в unit-тестах; эти тесты не доказывают физическую работу пылесоса.

Discovery: в QA HA не увидел Bluetooth-адаптера; сетевых discovery flow не было. Это ограниченное наблюдение внутри контейнера, а не доказательство отсутствия устройств в домашней сети.

## Windows после обновления

Версия 0.2.0 подтверждена на реальном Windows через новый разрешённый туннель. Нижняя правая кнопка, открытие nonmodal-чата, черновик после перехода в настройки и защищённая форма Telegram прошли проверку. Ошибок страницы не было. Полный чат-сценарий не прошёл: запрос через OpenCode возвращает `model_error`, хотя прямая проверка DeepSeek с инструментом успешна. См. `windows-after-update.json`. Настройки и устройства не менялись; отправлены только тестовые сообщения.

Точная причина ещё не установлена: изолированный OpenCode с deepseek-flash принимает новые и сохранённые диалоги и выполняет read-only инструменты. Для локальной диагностики подготовлен `diagnose-assistant.bat`, который читает только ограниченные сведения об ошибках; шесть тестов проверяют read-only доступ, границы и отсутствие секретов в выводе. Выполнение этого BAT на Windows пока ожидается.
