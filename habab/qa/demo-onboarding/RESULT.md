Предпросмотр доступен по адресу https://habab-demo.wpmix.net/?habab-preview=onboarding.

Чат открывается сразу. Первое сообщение содержит вопрос об оборудовании,
сводку трёх виртуальных сущностей из существующего PostgreSQL-backed API и
быстрые ответы. Это снимок состояния при открытии, без фонового опроса.
На компьютере справа открыта панель, слева остаётся дашборд HA. На узком экране
чат занимает окно; строка ввода и отправка находятся вне прокручиваемой истории.

Быстрый ответ проходит через тот же API, хранилище и DeepSeek. Явный режим
`onboarding` сначала уточняет модель, тип и подключение устройства. Исходный
публичный чат сохраняет прежние prompt и запрос; URL без preview загружает
прежний модуль v5. Приватные установки, Telegram и лендинг не развёртывались.

Проверено:

- 24 Python-теста и 12 subtests; 30 JavaScript-тестов.
- Chromium 1280×800 и 390×844: открытие, первая сводка, быстрый ответ,
  ручной ввод → Enter → ответ, сохранение черновика, видимая отправка во время
  запроса, отсутствие публичного административного hook.
- При уменьшении высоты до 420 px ввод и отправка остаются внутри viewport.
- Пять настоящих ответов DeepSeek прочитаны вручную: Xiaomi, требование
  подключить неизвестный пылесос, Zigbee, неизвестное оборудование и Tuya.
  Ассистент уточняет сведения и не заявляет выполненного подключения.
- При намеренной ошибке API состояния показана ошибка с повтором; вымышленные
  значения не появляются. Ошибка `Demo state is unavailable` относится только
  к этой искусственной проверке. В обычных сценариях page errors отсутствуют.
- Обычное демо отдельно проверено до и после: чат закрыт, прежний модуль не
  изменён. Созданные browser contexts закрыты, чужие страницы сохранены.
- SHA публичного preview-модуля совпал с исходником; `release.json` содержит
  точные хеши. Сборка компилятора HA не запускалась.

Первый прогон `dialogue-result.json` выявил слишком ранние и неподтверждённые
рекомендации. После изменения preview-контекста выполнен новый полный прогон
`final-dialogue-result.json`; прежний результат сохранён для сравнения.

Как проверить: открыть preview, выбрать «Xiaomi Home», дождаться уточняющего
ответа. Ввести собственный вопрос и отправить Enter. Для повторения проверки
используются `node habab/qa/demo-onboarding/check-dialogue.cjs` (обращается к
реальному платному API через существующий демо-сервис) и
`python3 habab/build/publish_chat_preview.py` (только показывает план).
Публикация preview: та же команда с `--publish`; модуль сохраняется по SHA,
entrypoint заменяется после записи файлов.

Ограничения: мобильная клавиатура проверена уменьшением viewport, без физического
телефона. Подключение реального оборудования и Windows через support tunnel в
этот прогон не входили. Для Windows ожидается свежий вывод пользовательского BAT.
