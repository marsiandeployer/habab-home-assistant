# Yandex SpeechKit в голосовом Assist

Habab Home добавляет отдельную Home Assistant integration `habab_yandex_speech` для SpeechKit STT и TTS. Она использует актуальный Yandex SpeechKit REST API v1. Встроенная HA integration `yandextts` остаётся отдельной legacy версией: её документация требует старый API-ключ и YAML настройку, STT она не предоставляет.

## Подключение

После включения `habab_yandex_speech` в сборку откройте **Настройки → Устройства и службы → Добавить интеграцию** и выберите **Habab Yandex SpeechKit**. Веб-чат пока не перечисляет все доступные, но ещё не настроенные интеграции: он показывает подключённые записи. Поэтому не рассчитывайте, что чат найдёт этот flow по одному названию. Если запускаете setup action вручную, используйте точный домен `habab_yandex_speech`.

1. Вставьте API-ключ сервисного аккаунта Yandex Cloud с ролями `ai.speechkit-stt.user` и `ai.speechkit-tts.user`. Форма объясняет, что тестовый текст будет отправлен в Yandex, а запросы могут тарифицироваться.
2. Нажмите сохранение. Config flow отправляет короткую фразу в TTS endpoint. При ошибке авторизации, квоты, сети или ответа запись подключения не создаётся; ключ остаётся в защищённом вводе и не передаётся модели.
3. Откройте **Настройки → Голосовые помощники**, выберите STT и TTS **Habab Yandex SpeechKit** в нужном Assist pipeline и выберите отдельного conversation agent. Проверьте настройки pipeline перед нажатием микрофона: русский аудиоввод отправляется в Yandex SpeechKit.
4. Команда из Habab-чата после распознавания направляется выбранному runtime Habab. Yandex здесь отвечает только за STT/TTS; он не становится моделью, которая понимает команду.

Для сервисного API-ключа Yandex Cloud использует каталог сервисного аккаунта и не требует передавать `folderId`. Не вставляйте IAM-токен или API-ключ в обычное сообщение: setup-flow принимает только API-ключ в поле типа password. Он сохраняется в config entry Home Assistant и входит в резервную копию `/config`.

## Передаваемые данные и отказ провайдера

После выбора SpeechKit в pipeline Home Assistant отправляет записанную речь в Yandex STT, а текст ответа — в Yandex TTS. Распознанный текст затем поступает conversation agent из настроек pipeline. Для Habab-чата таким агентом остаётся выбранный runtime Habab. Это облачная обработка, не локальный режим.

Если Yandex не отвечает, вернул ошибку авторизации или квоты, Home Assistant показывает ошибку этапа STT/TTS. Интеграция не переключает запрос на OpenAI, другой STT или другой TTS. Выбранный conversation agent — отдельная стадия, которую можно настроить независимо.

## API и ограничения компонента

- STT использует `POST https://stt.api.cloud.yandex.net/speech/v1/stt:recognize`, формат raw LPCM, `ru-RU`, один канал, 16 кГц. API v1 принимает не более 1 МБ и 30 секунд; код ограничивает поток меньшим из этих пределов.
- TTS использует `POST https://tts.api.cloud.yandex.net/speech/v1/tts:synthesize`, русский голос `filipp`, ответ OggOpus. Код ограничивает URL-encoded тело запроса 15 000 байт и исходный текст 5000 символами; для кириллицы срабатывает байтовый лимит раньше.
- Ключ передаётся только в `Authorization: Api-Key …`; редиректы выключены. Ответы ограничены по размеру и времени. В журналах остаётся безопасный код ошибки без тела ответа и ключа.
- Проверка при настройке подтверждает доступ к TTS, но не отправляет пробную запись для STT. Русское распознавание проверяется при первой голосовой команде. Сервисному аккаунту нужны обе роли.

## Статус проверки

| Проверка | Результат |
|---|---|
| Config flow и защищённое сохранение ключа | Проверяются модульными тестами с замоканным HTTP; живой ключ не использовался |
| Контракты STT/TTS, ошибки API, лимиты и отсутствие fallback | Проверяются модульными тестами с замоканными HTTP-ответами |
| Физическая русская запись → транскрипт → действие → TTS | Не запускалось; для этого нужны ключ Yandex, согласованный тестовый дом и микрофон |
| Подключение через UI текущего опубликованного образа | Пока не проверено: источник компонента ещё требует включения в Docker image |

Значок подключения после сохранения означает, что короткий TTS-запрос прошёл. Он не доказывает точность русского STT на комнате или микрофоне. Не называйте стенд аппаратно принятым до проверки полного пути на целевой установке.
