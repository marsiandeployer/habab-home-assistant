# Проверка веба и Telegram: незавершённая приёмка

На реальном Windows через основной Chrome подтверждены Home Assistant Core 2026.10.2 и Habab Home 0.3.0. Проверка использовала только собственные фоновые вкладки; они закрыты после каждого сценария. Настройки, подключения провайдеров и устройства напрямую не изменялись.

Встроенный веб-помощник ответил на запрос только на чтение без `model_error`; диагностика: runtime running, error null. Ответ — 7 интеграций, 3 служебных устройства, пылесоса нет — совпал с независимыми native API/registry. В registry нет сущностей vacuum и интеграции Xiaomi Home. Это проверка фактического ответа, не полная аттестация внутренней tool trace.

В этой установке ещё нет нового интерфейса 0.3.1. Пылесос здесь не подключён, поэтому его фактическое отображение на Windows пока не принято. Подключение ожидает разрешения владельца: прежний Windows scope ограничивал проверку чтением.

В общем backend найден недостающий переход: начатая в Telegram настройка доступна в защищённой веб-карточке владельца, но исходный Telegram-чат не получал автоматическое подтверждение завершения. Исправление принято в исходниках: источник определяется по доверенной активной Telegram-сессии и привязке бота, сохраняется приватно и не попадает в модель или форму. Завершение отслеживается через native config-entry signal даже после закрытия веб-страницы. Сообщение отправляется только после loaded и повторной проверки действующего владельца, исходного bot ID и текущей привязки чата. Маркер доставки ставится после ACK; повторное обновление не дублирует подтверждённую отправку. Xiaomi сохраняет происхождение через обязательный перезапуск. Пароли, коды и OAuth остаются в веб-карточке/официальном сайте.

Реальный бот выделен только Android-сессии для единственного P30 worker. Эта проверка не запускает второго poller и не копирует токен. Настоящий Telegram → AssistantService → действие HA → ответ, окончание формы с возвратом результата в Telegram и физическое подключение Xiaomi ещё не приняты. Результаты unit tests сами по себе это не доказывают.

## Проверка исправления

В образе с SDK Home Assistant Core 2026.10.2 прошли 73 целевых теста. Независимый полный прогон — 112 Python tests — выполнен с сетью none, на изолированном экспорте принятого commit7e1cc2fd1 плюс ровно 10 файлов исправления. Исходники монтировались read-only; параллельная работа Android/Reatime/OpenAI исключена. Это source-overlay проверка, не новый baked image. Хеши замороженных файлов и вывод в python-validation.json.

Ревью выявило и помогло исправить два реальных пропуска: переход progress→loaded без веб-поллинга и привязку к исходному bot ID при перенастройке того же config entry. Повторное независимое ревью не нашло блокирующих замечаний. Проверены отсутствие приватного origin в public/model payload, отсутствие ложных уведомлений для web-only flow и подтверждение доставки только по ACK.

Bot API не предоставляет idempotency key для sendMessage. Если Telegram принял сообщение, но ACK потерялся, разрешённая позднейшая повторная попытка может дать дубль. Отрицательный ACK не считается доказанной доставкой.

Опубликованный пакет0.3.1 не перезаписывался и этого backend-исправления пока не содержит. Исходники передаются Android-владельцу для следующего проверяемого runtime0.3.2. Реальный P30 bot E2E остаётся отдельным обязательным шагом.
