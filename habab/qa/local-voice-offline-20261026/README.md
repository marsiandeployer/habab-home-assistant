# Изолированный профиль: операторский каркас

Это disposable QA-проект для Home Assistant Core `2026.10.2`. Он не использует домашнюю конфигурацию, ключи, `configuration.yaml` владельца или установленный владельцем Home Assistant.

## Оценка диска перед загрузкой

Сумма сжатых слоёв pinned-образов, включая Core: 4,699,395,047 bytes для amd64. Для проектирования пика учтены четыре копии этой суммы (тройной запас на распаковку плюс одна сжатая копия во время pull), 3,044,033,499 bytes моделей, второй временный экземпляр Qwen blob (2,497,280,480 bytes), 2 GiB метаданных/служебных файлов и 10 GiB резерва. Полученный screening floor округлён вверх до **36 GiB свободного места на Docker storage filesystem**.

Это консервативная оценка, не измеренный размер распакованных image layers. Если реальная оценка Docker storage выше, действовать по большей цифре. Сейчас подготовку не запускать: по текущему read-only замеру родителя свободно около 22.7 GiB, меньше порога.

## Команды

Из этой папки:

```sh
python3 run.py --prepare
python3 run.py --run-offline
python3 run.py --run-synthetic-turn
python3 run.py --stop-offline
```

`--prepare` требует локальный Docker context, локальную файловую систему для Docker storage и минимум 36 GiB свободного места. До image pull он проверяет remote Ollama manifest digest; затем загружает только pinned images, по очереди запускает Wyoming Whisper и Piper через обычный bridge и сверяет модельные SHA-256. Ollama скачивает `qwen3:4b-instruct`, проверяет model blob digest и делает локальный warm-up запрос. Подготовительные контейнеры удаляются, именованные model volumes остаются. Этот этап требует временного WAN-доступа.

`--run-offline` никогда не выполняет pull. Он стартует только сервисы профиля `offline`, прикреплённые к Docker network `offline` с `internal: true`, затем повторно сверяет SHA-256 локальных голосовых файлов и Ollama model blob. Единственный опубликованный порт — `127.0.0.1:18444` для интерфейса этой копии HA. Wyoming и Ollama доступны только сервисам QA-сети. При отсутствующем образе команда завершится ошибкой; при отсутствующей модели внешняя сеть недоступна и fallback не настроен.

`--run-synthetic-turn` работает только с уже запущенными контейнерами этого проекта и ничего не поднимает. Один раз открой loopback UI и создай временного локального администратора HA. В его профиле выпусти Long-Lived Access Token, затем запусти команду в интерактивном терминале и введи токен в скрытый prompt. Runner передаёт его только helper-функциям в памяти. После проверки отзови токен в HA. Helper откажется продолжать, если найдёт ранее добавленные Wyoming/Ollama entries, одноимённый pipeline или другую fixture-сущность. Не удаляй и не переинициализируй именованный config volume автоматически; для повторного запуска с конфликтующей конфигурацией подготовь чистый disposable volume отдельно.

Runner создаёт WAV фразы «Включи тестовую лампу» через `espeak-ng` только во временной папке и удаляет его после turn. Helper штатными HA config flows добавляет локальный Whisper, Piper, Ollama и русский Assist pipeline, ограниченный `light.qa_virtual_light`; затем отправляет synthetic audio через Assist pipeline, проверяет stages, модельный route, TTS и состояние лампы. Воспроизведения звука нет. Helper возвращает `llm_invocation_status=NOT_RECORDED`; runner дополняет результат счётом успешных `POST /api/chat` в последних максимум 200 строках доступа только своего Ollama-контейнера до и после запроса. В памяти остаётся только число и проверенный route; строки логов не выводятся и не сохраняются. Если логи не дают положительной дельты, весь локальный LLM сценарий считается неподтверждённым.

`--stop-offline` удаляет контейнеры и внутреннюю сеть проекта, оставляя именованные volumes для повторной проверки или последующей очистки оператором.

Операторские команды требуют явный режим. Без одного из четырёх флагов runner завершается до вызова Docker. Перед стартом он проверяет `bind()` на `127.0.0.1:18444`; к HTTP-портам других приложений не обращается. Для Docker CLI создаётся временный пустой config и выбирается только локальный `default` context; личный Docker config/credentials не читаются. Runner принимает только filesystem types `ext4`, `xfs`, `btrfs`, `zfs`, `f2fs` и `overlay`; неизвестный или сетевой тип приводит к остановке. Контейнеры, сети и volumes имеют owner labels; остановка сверяет их перед `compose down`.

Этот runner пока не запускал сервисы, модель или голосовой turn. `internal: true` изолирует Docker network от внешних сетей, но реальный WAN egress ещё требует отдельного внешнего счётчика и остаётся **не проверен**.
