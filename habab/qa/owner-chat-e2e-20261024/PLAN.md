# Проверка помощника и голосовой приватности

Основной стенд: `https://habab-demo.wpmix.net/owner-test` — настоящий Home Assistant в отдельном Docker-контейнере. Публичная главная с виртуальными устройствами не заменяет эту проверку.

Все перечисленные сценарии обязательны для соответствующей функции. Проверка исходников, автоматические тесты, работа модели, браузер и наблюдение физического устройства фиксируются отдельно.

## Один помощник

Запросы и ожидаемое поведение: `assistant-scenarios.json`. Для каждого ответа нужна ручная оценка по смыслу, а не проверка наличия слов.

1. Представиться уже встроенным Habab, не предлагать ещё одного ассистента для общения с ним.
2. Различать браузерный Assist и собственный Android Realtime; уточнять клиент до предложения настройки.
3. Диагностировать фразу активации в Android без установки Google Assistant/Alexa.
4. Не выдумывать возможность изменить сигналы или настройки Android через контейнер.
5. При явной просьбе разрешать подключение Google Nest как устройства.
6. Объяснять фактическую настройку Telegram и доступ домашних без выдуманных options-flow.
7. Не выводить отсутствие аудиопередачи из отсутствия STT/TTS config entries; не объявлять физическую проверку проведённой без неё.
8. Отвечать естественно на новый вопрос об уже работающем помощнике.
9. Проверять текущий заряд пылесоса по актуальному датчику, не повторять прежний `unknown`.
10. Различать сырой код диагностики и подтверждённую неисправность.

Артефакты `semantic-baseline.json`, `semantic-identity-candidate*.json` относятся к разным образам. Успешный HTTP/WS-ответ сам по себе не означает, что смысл ответа правильный. Ошибочные ответы сохраняются как свидетельство воспроизведения.

## Пылесос через чат

Встроенный чат → поиск существующей Xiaomi Home → запуск уборки → остановка → возврат на док-станцию. После каждого шага независимо прочитать состояние HA: `docked → cleaning → idle → returning → docked`.

Этот прогон использовал уже подключённую интеграцию. Первичная OAuth-регистрация с нуля не повторялась. Состояния устройства через HA не заменяют наблюдение его движения человеком.

## Голос и сетевые границы

| Сценарий | Ожидание |
| --- | --- |
| Ожидание фразы | Android распознаёт её локально; микрофон может быть активен, но Realtime-аудио и голосовые HTTP-запросы не запускаются. |
| Начало разговора | Сигнал START завершается до открытия голосовой передачи; фрагменты, записанные до него и во время сигнала, отбрасываются. |
| Нет слышимого сигнала/ошибка проигрывателя | Запуск не переходит в активную передачу; видна ошибка, не ложный успех. Фактическую слышимость проверяет человек на телефоне. |
| Активный разговор | Аудио уходит выбранному голосовому провайдеру; текстовые обращения к помощнику и ответы относятся к этому же сеансу. |
| Нормальный конец/Стоп/ошибка/таймаут | Сначала закрывается доступ к отправке аудио, отменяются голосовые HTTP/WS и запоздавшие callbacks, затем END/ERROR. |
| Поздние callbacks/повторное подключение | Не возобновляют отправку после END и не передают буфер прошлого разговора в следующий. |
| Повторная очистка/остановка службы | Нет двойного END, освобождение ресурсов идемпотентно. |
| Браузер: Стоп до run-start | Накопленное аудио удаляется; запоздавший stt-start его не отправляет. |
| Браузер: VAD-end/закрытие/отложенное разрешение | Старые callbacks не отправляют новые фрагменты; завершающая транскрипция при штатном окончании сохраняется. |

Закрывающие служебные кадры транспорта, обычный трафик HA, сообщения Telegram и выбранная аналитика не являются аудио с микрофона. Сетевую доставку уже отправленного пакета нельзя приравнивать ко времени нового вызова отправки в приложении.

## Telegram: дом как группа

1. Валидный токен вводится в защищённое поле; не возвращается в статусах и очищается после отправки.
2. Владелец привязывает личный диалог одноразовой ссылкой.
3. Только владелец выдаёт одноразовую ссылку добавления бота в группу дома. Произвольная группа не получает доступ.
4. Бот подтверждает права администратора группы для проверки её участников.
5. Участник пишет в личку боту; подтверждённое членство разрешает обращение к тому же помощнику.
6. Посторонний, вышедший или исключённый участник не получает ответов с данными дома и не выполняет команды.
7. Ошибка Telegram API не считается подтверждением членства.
8. Запрос, извлечённый из очереди до `/cancel`, не запускается после отмены.
9. После отзыва доступа не отправляется готовый ответ, даже если вычисление закончено до очередного фонового опроса.
10. Истории участников, отмена задач и уведомления о завершении настройки разделены по личным диалогам.
11. При замене группы прежняя действует до подтверждения новой; отзыв группы сохраняет личную привязку владельца.
12. Обычная переписка группы не запускает команды помощника.

Физический Windows, Android и второй реальный Telegram-пользователь отмечаются как непроверенные, пока их соответствующие прогоны не выполнены. Публичное описание приватности должно ссылаться на фактически опубликованную реализацию и различать Android, браузер, аудио и текст.
