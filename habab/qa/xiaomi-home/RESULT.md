# Xiaomi Home: проверка 22 октября 2026

Старая интеграция `xiaomi_miio` на закрытой тестовой установке вернула
`cloud_login_error` с регионом `ru`. Это не доказывает ошибку пароля.

Официальная `XiaoMi/ha_xiaomi_home` v0.5.0 установлена из закреплённого исходного
кода с проверкой SHA-256. Native flow прошёл EULA, выбор России и создание
OAuth-ссылки. Вход на `account.xiaomi.com` дошёл до проверки личности по email;
отправлен код владельцу. **Подключение аккаунта, получение списка домашних
устройств и управление физическим устройством не подтверждены:** нужен код.
Логин, пароль, OAuth state/code и токены в отчёт и пакет не входят.

Новый `start-xiaomi-home.bat` устанавливает компонент при запуске для личного
использования, проверяет порт 8123 и добавляет Windows callback alias после UAC.
В публичный ZIP входят наши installer и metadata; исходники Xiaomi не включены.

В настоящем Core команда помощника `devices` больше не возвращает 400;
`devices` и `discovered_flows` вернули пустые списки. Тесты проверяют iterable API
реестра, владельца flow, фильтрацию discovery sources и исключение defaults/
секретов из форм. Поддержка discovery не доказывает физическое сопряжение.

Проверки: 24 native unit tests в финальном образе; 22 Flask/relay/installer tests
и 18 subtests; PowerShell parser; шесть случаев разбора hosts-файла; SHA-256
скачанного по публичному HTTPS Windows ZIP. Исходники работающего нового образа
совпали с локальными файлами. Нативный UI телеметрии на новом образе проверен
в Chromium 1280×800 и 390×844 без ошибок страницы/API и горизонтальной прокрутки.
Физический Windows, Docker Desktop/WSL, UAC и аппаратные адаптеры не проверялись.

Старый минимальный QA без Recorder давал `unknown_command` для `recorder/info`.
Для финальной браузерной проверки создан отдельный Core с `default_config`;
на нём эта ошибка отсутствует. OAuth flow оставлен на исходном закрытом QA,
публичный анонимный demo не подключался к аккаунту Xiaomi.
