# Habab Home 0.3.0

Для проверки на Windows: [запуск батником](README-WINDOWS.md). Он устанавливает недостающее ПО и открывает локальный Home Assistant; API-ключи в пакет не входят.

Архив предыдущей версии исходников и установочных файлов: [`habab-home-0.1.0.zip`](https://habab.ru/downloads/habab-home/habab-home-0.1.0.zip).
Это небольшой пакет для локальной сборки, не готовый Docker-образ и не полный
upstream-репозиторий Home Assistant.

Habab Home — локальный Docker-дистрибутив на основе Home Assistant Core
2026.10.2. Полный frontend собран из соответствующего upstream tag
`20260930.4` с патчем `habab.3` и установлен как SHA-256-закреплённый wheel при
сборке Docker-образа. Установка проверяет размер, digest и источник артефакта;
версия Core при этом остаётся 2026.10.2. Интеграция добавляет защищённый
статусный API, разделы AI и Telegram, один глобальный чат и нативные Assist
подключения. [Инструкция помощника](../docs/SETUP-ASSISTANT.md). OpenCode
запускается внутри контейнера; общий с хостом только исполняемый файл через
read-only mount.

Образ предназначен для Linux с Docker Engine и Compose v2. В него не входят
Home Assistant OS, Supervisor, add-ons, облачный аккаунт, GPU или языковая
модель. При первом запуске штатный мастер Home Assistant создаёт владельца.
Заранее заданных пользователей, паролей, API-токенов и пользовательских
настроек в репозитории нет.

## Установка

Из этого каталога выполните:

```sh
cp .env.example .env
docker compose build
docker compose up -d
docker compose logs -f homeassistant
```

При первой сборке Docker скачает закреплённый базовый образ Home Assistant с
`ghcr.io` — около 2,36 ГБ. На время сборки нужен доступ к этому реестру и
свободное место на диске. После сборки основной профиль работает локально; для
Home Assistant аккаунт Habab или облачное подключение не нужны.
Для установки нужен также доступ к публичному SHA-256-закреплённому frontend
wheel, который Dockerfile устанавливает без дополнительных зависимостей.

Если сборка или запуск не проходят, напишите на `mail@habab.ru` или в Telegram
`@onoutnoxon`. Приложите версию Docker и фрагмент ошибки; не отправляйте `.env`,
пароли, токены, резервные копии или полные конфиги.

Сначала откройте `http://127.0.0.1:8123` на самом сервере и завершите первый
запуск Home Assistant. По умолчанию порт доступен только с localhost. Чтобы
открыть систему с других домашних устройств, задайте в `.env` адрес LAN
интерфейса сервера в `HABAB_HOME_BIND`, затем пересоздайте контейнер командой
`docker compose up -d`. Не указывайте `0.0.0.0` без необходимости и не
перенаправляйте порт из интернета. Соединение по HTTP предназначено для
доверенной локальной сети; TLS в этой версии не настроен.

Для сервера без монитора можно заранее задать его доверенный LAN-адрес в `.env` или открыть localhost через SSH-проброс порта. Первый пользователь создаётся только в штатном мастере; общих заводских паролей нет.

При первом старте образ копирует минимальный `configuration.yaml` в том
`habab_home_data`, только если такого файла ещё нет. Следующие запуски сохраняют
этот файл и остальные данные `/config`. Профиль включает штатные API,
конфигурацию и веб-интерфейс, но не `default_config`, облачные, аналитические,
удалённые оповещения или телеметрические интеграции. Позднее добавленные
интеграции могут связываться с локальными устройствами и выполнять сетевые
запросы согласно своим функциям.

Собственный `GET /api/habab_home/status` требует bearer-токен Home Assistant.
Ответ содержит версии дистрибутива и Home Assistant, без данных о пользователе,
сети или секретах. Без токена сервер отвечает HTTP 401.

## Обновление

Перед обновлением сверьте `release.json` и примечания к миграции выбранной
версии. Соберите образ и пересоздайте контейнер, сохранив том с данными:

```sh
docker compose build --no-cache
docker compose up -d --force-recreate homeassistant
```

Не запускайте `docker compose down -v`: эта команда удаляет постоянные тома.
Откат через версии Home Assistant, меняющие формат базы, может не поддерживаться.

## Резервная копия и восстановление

На время копирования остановите Home Assistant. Compose-проект называется
`habab-home`, поэтому при стандартном запуске том конфигурации называется
`habab-home_habab_home_data`. Команды ниже получают его имя из текущей Compose
конфигурации, чтобы сохранить совместимость с изменённым именем проекта:

```sh
volume_name=$(docker compose config --format json | python3 -c 'import json,sys; print(json.load(sys.stdin)["volumes"]["habab_home_data"]["name"])')
mkdir -p backups
docker compose stop homeassistant
docker run --rm -v "$volume_name:/data:ro" -v "$PWD/backups:/backup" alpine:3.22 \
  tar -C /data -czf /backup/habab-home-config.tgz .
docker compose start homeassistant
```

Архив содержит аккаунты, токены, интеграции и данные устройств. Храните его в
зашифрованном виде с ограниченным доступом. Для восстановления остановите
сервис и распакуйте архив в пустой том с тем же именем. Не распаковывайте архив
поверх существующих данных. Верните соответствующий `.env`, запустите сервис и
проверьте восстановленные настройки. До замены исходного тома проверьте
резервную копию и убедитесь, что восстановление прошло успешно.

## AI и голосовой помощник

Интеграция `habab_home` добавляет административный раздел **AI** (`/habab-ai`). В нём подключаются OpenAI, DeepSeek и Google Gemini, проверяются ключ и вызов инструментов, выполняются команды Assist. Для голоса OpenAI предоставляет распознавание и озвучивание; провайдер понимания команд выбирается отдельно. VAD выполняется в Home Assistant. [Настройка и ограничения](../docs/VOICE.md).

Ключи хранятся в локальных config entries Home Assistant и входят в резервные копии `/config`. Настройка облачного провайдера означает отправку ему текста и доступных Assist данных устройств; речевому провайдеру отправляется аудио. Публичное демо отделено от домашней установки.

## Чат помощника и Telegram

На страницах Home Assistant один и тот же чат открывается кнопкой в правом нижнем углу: на компьютере — немодальной панелью справа, на телефоне — на весь экран. Кнопка на странице AI ведёт в этот чат. Веб и Telegram используют общий `AssistantService` и приватный OpenCode runtime; история веба и каждого привязанного Telegram-чата хранится отдельно. Нативный Assist тоже вызывает `AssistantService`, но адаптер передаёт модели только инструменты, открытые для выбранной конфигурации Assist. У этого канала нет доступа к OpenCode и root.

Раздел **Telegram** в боковом меню доступен только администратору. Защищённое поле сохраняет токен BotFather в нативной записи HA; одноразовая ссылка привязывает личный чат. Веб, каждый Telegram-чат и нативный Assist используют общий сервис и настройки провайдера, сохраняя отдельные истории и контексты. Карточки flow в веб-чате используют native `step-flow-form` и HA context host, сохраняя штатные переводы, selectors и проверку формы. Модель получает `input_fields` только с именами, типами и обязательностью полей. Defaults, варианты выбора, подписи, введённые значения и URL остаются вне prompt. Значения отправляются из формы напрямую в owner-scoped WebSocket-команду `habab_home/setup/*`, не в историю, Telegram или логи. Для пароля, OAuth и других защищённых шагов Telegram направляет владельца в веб-интерфейс. Публичная демо-форма Telegram не подключает бота.

## Zigbee2MQTT по желанию

Compose-профиль `zigbee` запускает Mosquitto и Zigbee2MQTT. USB-координатор
передаётся только Zigbee2MQTT. Не подключайте это же устройство к Home
Assistant или другому Zigbee-процессу. Нужны Linux-хост и координатор по пути из
`Z2M_SERIAL_DEVICE`. Поиск устройств, сопряжение, прошивка и работа радио в этом
программном MVP не проверялись.

В незакоммиченный `.env` задайте собственные `MQTT_USER` и `MQTT_PASSWORD`.
Установите пакет `mosquitto` в Debian/Ubuntu, если команды
`mosquitto_passwd` ещё нет. Укажите то же имя пользователя, что в `.env`;
пароль команда запросит интерактивно:

```sh
mkdir -p secrets
mosquitto_passwd -c secrets/mosquitto-passwd hababzigbee
docker compose --profile zigbee up -d
```

Если вместо `hababzigbee` указали другое имя, поменяйте его и в `.env`. Введите
в `.env` тот же пароль, который задали команде. `.env` и файл паролей исключены
из Git. Не вводите секреты в командную строку, историю оболочки или общий
терминал.

## Исходники и лицензии

Версия и неизменяемый digest базового образа указаны в `release.json`. `Dockerfile`
добавляет интеграцию `habab_home` в Python-пакет Home Assistant Core, минимальную
начальную конфигурацию и безопасное заполнение пустого каталога данных, а также
метки Habab Home 0.3.0. `NOTICE` указывает на upstream-проект и разъясняет, что
Habab Home — независимый дистрибутив. Для Docker поставляется полный frontend
`20260930.4+habab.3`. `install-native-frontend.py` сверяет закреплённые версию,
имя, размер, HTTPS origin и SHA-256 wheel до установки. В той же сборке находятся
API bridge v1 и native `step-flow-form` с context host на базе HA `contextMixin`;
они сохраняют штатные callbacks полей, переводы, selectors и валидацию. Core
при этом остаётся на 2026.10.2.

Код Home Assistant Core распространяется по Apache-2.0. Собственные изменения
в этих каталогах также лицензированы по Apache-2.0; см. `LICENSE` и источник в
`release.json`. Название и логотипы Home Assistant остаются собственностью
правообладателей. Проект не связан с Open Home Foundation или Home Assistant и
не одобрен ими.

## Проверенный объём и ограничения

Локальный образ собран и проверен на amd64 без source overlays. Готовый GHCR-образ
не публиковался; Dockerfile загружает закреплённый frontend wheel и собирает
локальный образ. Release check для Habab Home 0.3.0 зафиксировал 100 Python
unit tests, 26 JavaScript tests, 10 native frontend tests, lint, pre/post-build
typechecks и успешный полный frontend build. Browser QA на изолированном Linux
образе прошёл 7/7 сценариев без ошибок страницы. В них проверены общий чат,
маршруты и mobile layout, native форма Time & Date до создания загруженной
сущности реального времени и подтверждения её состояния, а также selector
context matrix. Последний использует синтетические данные, без отправки формы.
После исправления холодного старта
bootstrap не дал ошибок и не вызывал Recorder, когда тот отключён; конфигурация
не менялась. Сводный отчёт, браузерный сценарий и bootstrap-проверка находятся
в `habab/qa/canonical-assistant/release-check.json`,
`habab/qa/canonical-assistant/browser-result.json` и
`habab/qa/canonical-assistant/bootstrap-after-fix.json`.

Отдельный model benchmark на изолированном образе завершился `PASS_WITH_LIMITS`
для семи запросов; отчёт — `habab/qa/canonical-assistant/model-benchmark-final.json`.
HA отклонил пустой запрос продолжения формы кодом 400; запись интеграции не
появилась. Форму в этом benchmark не отправляли, команды управления устройствами
не выполняли. Оба результата относятся к изолированному Linux QA.
На Windows установлена версия 0.2.0: интерфейс прошёл UI-сценарии, но запрос
OpenCode вернул `model_error`; причина не установлена. Habab Home 0.3.0 на
физической Windows, живой Telegram-бот и управление физическими устройствами не
проверялись. ARM64, будущая Linux-коробка, USB-доступ, Zigbee-радио и работа
физических устройств без WAN требуют отдельного аппаратного пилота. Облачный
сервис не реализован. Home Assistant Core и добавленные владельцем интеграции
сохраняют собственное поведение за пределами минимального профиля проекта.
