# Установка и первый запуск Habab Home

Habab Home — локальный Docker-дистрибутив Home Assistant. На [странице загрузки Habab Home](https://habab.ru/home-assistant) опубликован Windows ZIP 0.3.1. В текущем checkout интеграция `habab_home` объявляет версию 0.3.6 в `const.py` и `manifest.json`, а `release.json` и Compose tag содержат 0.3.4. Это разные версии компонентов и пакета; Windows ZIP остаётся отдельным стабильным выпуском. Остальные разделы описывают текущий исходный код; расположение отдельных элементов в ZIP 0.3.1 может отличаться.

## Windows

1. Установите и запустите Docker Desktop для Windows. Дождитесь статуса **Engine running**.
2. Скачайте Windows ZIP, распакуйте его в постоянную папку и запустите `start-windows.bat`. Если Windows или Docker Desktop запросит перезагрузку, сделайте это и снова запустите BAT из той же папки.
3. Откройте [http://127.0.0.1:8123](http://127.0.0.1:8123) и создайте владельца Home Assistant. Готовой пары логин/пароль в пакете нет.
4. В разделе **AI** добавьте собственного провайдера и проверьте подключение. После входа администратора откроется чат Habab Home.

BAT из Git checkout находится в `habab/distribution/start-windows.bat`. Для запуска исходников клонируйте репозиторий и запустите отслеживаемый файл из корня:

```powershell
git clone https://github.com/marsiandeployer/habab-home-assistant.git
cd habab-home-assistant
.\habab\distribution\start-windows.bat
```

Так запускается текущий исходный кандидат, а не опубликованный пакет 0.3.1. Повторный запуск использует сохранённый том HA. Перед обновлением исходников выполните `git pull`, затем снова запустите BAT. Не удаляйте Docker volume и не используйте `docker compose down -v`, если хотите сохранить аккаунт и настройки.

Публичный пакет можно сверить по SHA-256 из [Windows manifest](https://habab-demo.wpmix.net/downloads/windows-package.json). На дату этой инструкции manifest указывает `habab-home-windows-dcfbe4740bb6.zip`, 144222 байта, SHA-256 `dcfbe4740bb6f39044bd14c66a449a7b02d626a28f6405990cc301161748825f`. Для архива в стандартной папке загрузок выполните `Get-FileHash "$env:USERPROFILE\Downloads\habab-home-windows-dcfbe4740bb6.zip" -Algorithm SHA256` и сравните результат с manifest. Перед ручной загрузкой сверяйте текущий manifest: опубликованные версии меняются отдельно от исходного кандидата.

## Docker на Linux

Установите Docker Engine с Compose v2, скачайте исходники, затем из корня репозитория выполните:

```sh
cd habab/distribution
cp .env.example .env
docker compose build
docker compose up -d
```

Откройте `http://127.0.0.1:8123` на компьютере с Home Assistant и создайте владельца. Дополнительные параметры сборки, LAN-доступа, обновления и резервного копирования собраны в [инструкции Docker](../distribution/README.md).

На Windows-пакете порт привязан к `127.0.0.1`; с другого устройства домашней сети он не доступен. Linux Compose по умолчанию также слушает localhost. Для доступа из локальной сети задайте `HABAB_HOME_BIND` на LAN-адрес сервера и пересоздайте контейнер по инструкции Docker. Не открывайте порт 8123 в интернет. Wi-Fi-устройство сможет обнаружиться, если сервер и устройство доступны в одной домашней сети, а интеграция поддерживает обнаружение через её маршрутизатор и настройки multicast. Это условие сети, а не результат проверки конкретного роутера.

## Подключите первое устройство

Войдите администратором, откройте чат Habab Home и попросите подключить нужную интеграцию, например: «Помоги подключить лампу». Помощник запускает штатный flow Home Assistant. Выборы и значения вводите в защищённой native-форме; пароли и OAuth не отправляются модели, в историю чата или Telegram. Проверьте результат в **Настройки → Устройства и службы** и в состоянии сущности. Установка интеграции не гарантирует совместимость каждого устройства.

Bluetooth и USB зависят от хоста и доступа контейнера. Docker Desktop не передаёт Bluetooth Windows адаптеру HA автоматически. Команда поиска показывает ограниченные наблюдения Home Assistant, а не сканирует Wi-Fi и не подтверждает сопряжение.

### Zigbee

Поддерживаемый в репозитории пример — опциональный Compose-профиль Zigbee2MQTT на Linux с USB-координатором, доступным хосту. Координатор использует только Zigbee2MQTT; не подключайте его одновременно к другому процессу. Профиль требует собственных MQTT-учётных данных и отдельной настройки. Подробные команды приведены в [разделе Zigbee2MQTT](../distribution/README.md#zigbee2mqtt-по-желанию). Физический координатор, радио и сопряжение устройств этим программным примером не подтверждены. Не используйте его как инструкцию для Windows Docker Desktop.

## Провайдеры, голос и Telegram

В разделе **AI** выберите OpenAI, DeepSeek или Google Gemini и введите свой API key в защищённое поле. Habab — отдельный провайдер и требует отдельный ключ от администратора сервиса. Нажмите **Проверить и сохранить**. Ключ сохраняется в локальной записи Home Assistant; обычный чат и Telegram используют выбранный сервис. Запросы и доступные помощнику данные устройства отправляются выбранному провайдеру. Публичное демо отдельно от домашнего сервера и не управляет его устройствами. Подробности и ограничения — в [руководстве AI и голоса](VOICE.md).

Голосовой сценарий требует провайдера понимания команд и настроенного Assist pipeline с распознаванием и озвучиванием. В исходниках порядок такой: подключить OpenAI для STT/TTS, выбрать провайдера команд, открыть **Настройки голосовых помощников**, выбрать и настроить pipeline, проверить доступные Assist-устройства. Затем нажать микрофон в чате и разрешить доступ браузера. DeepSeek или Gemini могут обрабатывать распознанный текст, а OpenAI — распознавать и озвучивать речь. Для браузерного микрофона нужен localhost или HTTPS. Панель не включает постоянное прослушивание или wake word. Подробности — в [руководстве голоса](VOICE.md). Голосовую работу на реальном доме, физическом микрофоне и Windows-пакете текущего кандидата не подтверждали.

Telegram подключает администратор в разделе **Telegram**: создаёт собственного бота через `@BotFather`, вводит токен в защищённую форму и привязывает личный чат владельца одноразовой ссылкой. По желанию администратор создаёт привязку доверенной группы; участники пишут боту лично, сообщения в самой группе игнорируются, состав проверяется. Не публикуйте ссылку привязки или токен. Защищённые формы настройки из Telegram открываются в веб-интерфейсе. Команды `/cancel` и `/new` доступны в личном чате; другие команды этой инструкцией не обещаются. Пошаговая процедура — в [руководстве чата и Telegram](SETUP-ASSISTANT.md).

## Примеры для дома

Это идеи для собственных устройств, не готовые сценарии или подтверждённые установки:

- **Квартира:** подключить одну лампу, назвать её по комнате, затем добавить свою автоматизацию выключения света.
- **Дом:** разнести доступные датчики и свет по помещениям, после чего отдельно настроить уведомления или расписание.
- **Дача:** добавить совместимые датчики протечки и температуры. Для управления издалека даче нужны интернет и защищённый удалённый доступ к Home Assistant. Не перенаправляйте открытый порт 8123 из интернета; используйте настроенный VPN либо HTTPS-доступ с аутентификацией. Такой доступ не включён автоматически и зависит от отдельной настройки сети.

Для каждой идеи сначала подключите устройство штатной интеграцией и проверьте его фактическое состояние. Приложение не содержит готовых квартирных, домашних или дачных пресетов.

## Обновление, копия данных и поддержка

Для исходной Windows-установки обновите Git checkout (`git pull`) и снова запустите `habab/distribution/start-windows.bat`. Для Docker обновите исходники, проверьте `release.json`, затем соберите образ и пересоздайте сервис, сохранив volume. Перед обновлением сделайте копию `/config`; пошаговые команды резервного копирования и восстановления есть в [инструкции Docker](../distribution/README.md#резервная-копия-и-восстановление). Архив содержит пароли, API keys и настройки интеграций: храните его зашифрованным и с ограниченным доступом.

Если нужна помощь, напишите на [mail@habab.ru](mailto:mail@habab.ru) или в [Telegram Habab](https://t.me/onoutnoxon). Приложите версию пакета и краткую ошибку. Не отправляйте `.env`, токены, пароли, полную резервную копию или конфигурацию. Временный доступ поддержки настраивается отдельно через [support tunnel](../support/README.md); он не создаёт логин HA и не выдаёт поддержке доступ к Windows или Docker API.

## Статус проверок и видео

Репозиторий содержит программные проверки и изолированные браузерные сценарии. Они не подтверждают физическую Windows-установку текущего кандидата, работу реального Telegram-бота, Zigbee-радио, USB/Bluetooth или оборудования в квартире, доме либо на даче. Результаты новых установок фиксируйте отдельно с моделью хоста, версией и фактически подключёнными устройствами.

Видео установки и подключения оборудования ещё не снято. Раскадровка для будущей съёмки:

1. Показать реальный компьютер и коробку координатора; назвать модели оборудования и версию пакета.
2. Запустить Windows BAT или Docker-команды, показать создание владельца в Home Assistant.
3. Подключить физический датчик/лампу штатным flow и показать изменение его реального состояния.
4. Показать собственную автоматизацию и отдельно проверить её на устройстве.
5. Если показывается дача, показать подключение к интернету и настроенный защищённый удалённый доступ.

Каждый кадр с аппаратурой должен быть снят на соответствующей физической установке. Макеты, виртуальные сущности и интерфейс публичного демо нельзя подписывать как работу оборудования.

Технические ссылки Home Assistant: [LAN и удалённый доступ](https://www.home-assistant.io/docs/configuration/remote/), [Zigbee Home Automation](https://www.home-assistant.io/integrations/zha/), [автоматизации](https://www.home-assistant.io/docs/automation/). Сведения об upstream относятся к техническим возможностям Home Assistant, не к проверенной установке Habab.
