# Habab Home для Android

Предварительная APK для Huawei P30 Pro VOG-L29, ARM64, без root. Приложение
управляет серверным процессом Home Assistant и открывает его интерфейс в
WebView. В окружение входят наши панели, чат OpenCode, настройка Xiaomi и
Telegram-компонент из текущего Docker-пакета. Данные установки хранятся на
телефоне; Windows нужен для первоначальной установки и отладки через USB.

Сборка APK и проверки на сервере не подтверждают работу на Huawei. Физическая
приёмка, выполнение команды OpenCode, автозапуск и 48 часов работы с
выключенным экраном обязательны перед использованием как постоянного сервера.

## Сборка

Нужны Java 17, Gradle 8.5, Android SDK с `platforms;android-34` и
`build-tools;34.0.0`, Python 3, Docker, OpenSSL, `dpkg-deb`, `readelf` и
`patchelf`. Android-проект независим от сборки Lit frontend.

Для холодной сборки окружения нужно не менее 8 GiB свободного места на
сервере; для повторной сборки с готовым rootfs — 2 GiB. Проверка распаковки
полного архива требует ещё 4 GiB. Сборщик проверяет место до экспорта образа.

Из корня репозитория:

```sh
python3 habab/android/tools/prepare_native.py
python3 habab/android/tools/prepare_voice.py

# Один постоянный ключ выпуска. Хранить вне репозитория и каталога downloads.
umask 077
mkdir -p "$HOME/.local/share/habab-android"
if [ ! -f "$HOME/.local/share/habab-android/release-signing.pem" ]; then
  openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:3072 \
    -out "$HOME/.local/share/habab-android/release-signing.pem"
fi

# Используйте полный SHA чистого коммита, который войдёт в выпуск.
python3 habab/android/tools/package_runtime.py \
  --signing-key "$HOME/.local/share/habab-android/release-signing.pem" \
  --source-revision "$(git rev-parse HEAD)" \
  --public-base https://habab-demo.wpmix.net/downloads/android

ANDROID_HOME=/opt/android-sdk gradle --no-daemon -p habab/android \
  :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
python3 -m unittest discover -s habab/android/tests -v
```

Ключ создаётся один раз: при повторной сборке используйте существующий файл.
`package_runtime.py` создаёт архив, JSON-манифест и подпись `.json.sig` в
`habab/android/dist/`. В APK попадают публичный ключ проверки и адрес выпуска.
Файл с приватным ключом в APK не входит. Ключ подписи APK и ключ подписи
серверного архива — разные ключи. Debug APK предназначена для отладки через
ADB; публикация приложения требует отдельной release-подписи.

PRoot и его библиотеки берутся из пакетов Termux с закреплёнными SHA-256.
`prepare_native.py` меняет пути динамических библиотек на `$ORIGIN` и
упаковывает инструменты в `nativeLibraryDir` APK. Пути загрузчика и временных
файлов передаются явно; установленный пакет `com.termux` не используется.
Полный терминал и пакетный менеджер в приложение не входят.
На P30 Pro создание жёстких ссылок внутри каталога приложения запрещено.
Распаковщик сохраняет такие файлы как отдельные копии с теми же правами;
их размер учитывается в общем лимите распаковки.
PRoot также оставляет пустые каталоги bind mount с правами `000`. При удалении
старого окружения приложение восстанавливает права владельца на такие
каталоги; символические ссылки при этом не обходятся.

Серверный архив строится из нового, ни разу не запущенного контейнера
официального ARM64-образа. Экспортировать домашний контейнер с аккаунтами и
ключами вместо него запрещено. Наши исходники копируются из
`habab/distribution/`; манифест фиксирует хеши каждого включённого файла.
Для Habab 0.3 также устанавливается закреплённый frontend wheel из
`native-frontend-release.json`: сборщик проверяет версию для Core, SHA-256 и
размер загрузки, затем устанавливает универсальный пакет для гостевого
Python. Подписанный выпуск содержит хеш установленного frontend вместе с
метаданными; `verify_runtime.py` проверяет его по полному архиву.
PRoot запускает Python напрямую, без Docker daemon и `/init`.
Служба передаёт Core `HABAB_RUNTIME_KIND=android_proot`, чтобы помощник
учитывал ограничения Android. UID 0 внутри гостя не даёт root на телефоне.

## Проверка выпуска

### Голосовой preview

Версия 0.1.5 добавляет отдельную службу микрофона с постоянным уведомлением и
кнопкой остановки. Включение — в приложении после входа в локальный сервер:
«Подключить голос к этому аккаунту», разрешение микрофона и настройка фразы.
По умолчанию используется «эй дом». Фраза распознаётся локально через Vosk;
доступны 1–5 слов из словаря русской модели. Неизвестное слово возвращает
ошибку. Произвольные придуманные имена модель может не поддерживать.

В кандидате native13 разговор ведёт Realtime-модель. Она отвечает на обычные
вопросы напрямую; для команд дому, настройки и недостающих свежих данных
вызывает общего помощника, предварительно произнеся «Секунду, проверю».
В начальный prompt входит краткая сводка времени и доступных состояний дома.
Явное прощание вызывает инструмент завершения текущего голосового сеанса.

START должен прозвучать полностью до первого сетевого запроса голосового
клиента. После сигнала приложение временно держит речь в памяти, пока
подключается провайдер; лимит ожидания — 8 секунд. Обычное завершение
останавливает аудиопередачу, дожидается принятых записей истории и проигрывает
END. Ошибка сохранения показывается явно. Аварийное закрытие может отменить
ещё не сохранённые записи. Аудиофайлы приложение не записывает.

OpenAI сохраняет пары реплик с идентификаторами провайдера. У Gemini Live
распознанные фрагменты и полностью проигранные ответы сохраняются отдельными
событиями с локальными идентификаторами: протокол не гарантирует связь
запоздавшей расшифровки с конкретным ответом. Общий журнал должен поддерживать
`record_voice_event`; без него сервер отклоняет запуск Gemini до запроса токена.

Выключенный экран поддерживается отдельной foreground-службой; полностью
выключенный телефон слушать не может. Native13 ещё не прошёл проверку на P30:
нужно отдельно проверить фразу, громкий динамик, эхо, перебивание, завершение
и работу с выключенным экраном. Серверные тесты с синтетической речью этого
не подтверждают. Последнее подтверждённое подключение, провайдер и голосовая
модель доступны в локальном `voice-status.json` → `lastConnection`.

Для Android объявляется локальное имя `homeassistant.local` по Wi-Fi или Ethernet.
Если в сети уже найден другой владелец имени, объявление не запускается;
причина доступна администратору в `/api/habab_home/status` → `lan_alias`.
mDNS требует одной локальной сети без изоляции клиентов; через мобильный
интернет это имя не работает. Статус `announced` подтверждает объявление,
но открытие с другого устройства проверяется отдельно.

На Android 10 системный браузер может не разрешать `.local`. APK также
регистрирует ссылку `http://homeassistant.local:8123`: если открыть её через
Habab Home в выборе приложений, оболочка направит запрос к своему
`127.0.0.1:8123`, сохранив путь страницы. Это обработка ссылки в приложении,
а не изменение системного DNS или hosts. В обычном Chrome поддержка имени
по-прежнему зависит от DNS/mDNS системы. На Windows локальную запись для
его собственного сервера приложение Android не меняет.

В разделе AI выберите провайдера для общего помощника. При выборе Habab
обычные запросы и Realtime идут через сервер Habab с отдельным клиентским
ключом. OpenAI использует прямой API. Gemini использует отдельный протокол
Live с моделью `gemini-3.8-live`; текстовая модель выбирается независимо.
Клиент получает одноразовый токен с ограниченным сроком, основной ключ остаётся
в серверном компоненте. Автоматического переключения провайдера после ошибки
нет. DeepSeek поддерживает текстовый чат,
но его ключ не используется для Realtime; в этом случае голос возвращает
сообщение о неподдерживаемом провайдере. Последняя безопасная причина ошибки
сохраняется локально и видна в настройках и уведомлении голосовой службы.

Telegram обращается к Bot API напрямую; необязательный HTTP-прокси задаётся
отдельно для бота. Глобального перенаправления OpenAI или Telegram через
Habab в Android launcher нет. [Сервер Habab и хранение ключей](relay/README.md).

Перед размещением файлов выполните:

```sh
python3 habab/android/tools/verify_runtime.py \
  habab/android/dist/release-RELEASE_ID.json \
  --public-key habab/android/app/src/main/assets/release/trusted-key.der

# Распаковка полного архива тем же Java-кодом, который используется в APK.
HABAB_RUNTIME_ARCHIVE="$PWD/habab/android/dist/habab-runtime-RELEASE_ID-arm64.tgz" \
  ANDROID_HOME=/opt/android-sdk gradle --no-daemon -p habab/android \
  :app:testDebugUnitTest --rerun-tasks
```

Ожидается `result: PASS` у проверяющего скрипта и успешное выполнение Java
тестов. Проверяются подпись, размер и SHA-256 архива, наличие Core, Node и
OpenCode, снимок исходников Habab и отсутствие приватных каталогов. Java-тесты
проверяют пути, ссылки, права файлов и распаковку реального окружения.

На HTTPS-хостинг загрузите только проверенные `.tgz`, `.json`, `.json.sig`
и APK. SDK, `build/`, конфигурацию домашнего сервера, ключи подписи и резервные
копии не публиковать. Сервер установки не должен перенаправлять запросы:
приложение принимает прямой HTTPS-ответ с кодом 200 и проверяет подпись до
скачивания архива. На телефоне одновременно нужны место для архива,
распакованного окружения и запас 256 MiB; предыдущая версия окружения также
занимает место при обновлении.

## USB и установка

1. Подключите Huawei к Windows кабелем, включите USB-отладку.
2. Запустите `connect-huawei-adb-yubikey.bat` из репозитория `kolya` от
   администратора, коснитесь YubiKey. Остальные сервисные туннели оставьте открытыми.
3. На телефоне подтвердите запрос USB-отладки. Окно туннеля оставьте открытым.

На сервере:

```sh
python3 habab/android/tools/device.py inspect \
  --adb /opt/android-sdk/platform-tools/adb --host 127.0.0.1 --port 18537
python3 habab/android/tools/device.py install \
  --adb /opt/android-sdk/platform-tools/adb --host 127.0.0.1 --port 18537 \
  --apk habab/android/app/build/outputs/apk/debug/app-debug.apk \
  --manifest-url https://habab-demo.wpmix.net/downloads/android/release-RELEASE_ID.json

# После запуска Core: проверить фактический флаг среды его процесса.
python3 habab/android/tools/device.py verify-runtime \
  --adb /opt/android-sdk/platform-tools/adb --host 127.0.0.1 --port 18537
```

`connect-huawei-adb-yubikey.bat` и соседние `.ps1` из `kolya` запускают
ADB 37.0.1 непосредственно на Windows для одного выбранного Huawei и передают
его протокол через отдельный SSH-порт 18537. Работающие браузерные, support и
SSH-туннели закрывать не требуется.
В этом режиме в команды `device.py` добавьте
`--adb /opt/android-sdk/platform-tools/adb --host 127.0.0.1 --port 18537`.
Команду `device.py attach` в режиме Windows ADB не выполнять. Установщик APK
использует `--no-streaming`, чтобы передача файла и установка шли отдельно.

Если первая установка возвращает `INSTALL_FAILED_VERIFICATION_FAILURE`,
проверьте сообщение установщика на разблокированном телефоне. Для ручной
установки APK можно скопировать в «Загрузки» и открыть через приложение
«Файлы». Подтверждение владельца ещё не доказывает установку: агент проверяет
наличие пакета через `pm path ru.habab.home`. Настройки защиты автоматически
не меняются.

`inspect` должен показать `VOG-L29`, ARM64 и версию Android. При `unauthorized`,
другой модели или нескольких телефонах автоматическая установка прекращается.
При необходимости задайте `--serial`. Скрипт не удаляет существующее приложение
при несовпадении подписи и не выполняет fastboot, прошивку или сброс телефона.

Параметр `install_url` обрабатывается только Debug APK. В обычном запуске
нажмите «Установить окружение»: адрес подписанного выпуска уже указан.
Загрузка и распаковка выполняются фоновой службой с уведомлением и wake lock.
После установки нажмите «Запустить сервер» и создайте владельца Home Assistant
через «Открыть умный дом». Готового пароля в пакете нет.

## Постоянная работа и внешний доступ

В настройках Huawei разрешите приложению автозапуск, вторичный запуск и
работу в фоне, отключите оптимизацию батареи для него и оставьте сеть активной
во время сна. Кнопка в APK открывает запрос исключения из оптимизации Android;
настройки EMUI могут потребовать отдельного изменения вручную.

Домашний адрес: `http://IP-телефона:8123`; на самом телефоне:
`http://127.0.0.1:8123`. Закрепите адрес в DHCP роутера. PRoot и Java-служба
не создают отдельную сетевую изоляцию и не предоставляют системный root.

Если Android запрещает `getifaddrs`, Python launcher использует адреса,
переданные `ConnectivityManager`. Переход записывается в лог. Неподдерживаемые,
пустые или устаревшие данные и ошибки, отличные от `EPERM`/`EACCES`, не
подавляются. Multicast lock разрешает приём Wi-Fi multicast; поиск реальных
устройств всё равно требует физической проверки.

Для HTTPS-доступа приложение создаёт свой SSH-ключ. На relay-сервер передаётся
только публичная часть из экрана настройки доступа. Выделенная SSH-учётная
запись должна разрешать лишь обратный проброс на один loopback-порт:
`AllowTcpForwarding remote`, `PermitListen 127.0.0.1:18123`, `GatewayPorts no`,
без shell, PTY, agent forwarding и пароля. В APK задаются адрес SSH,
пользователь, порт, закреплённый публичный host key и постоянный HTTPS-адрес.
Nginx на relay проксирует этот loopback-порт с поддержкой WebSocket и
`X-Forwarded-For`. Владелец должен настроить доверие к loopback-прокси через
нативные HTTP-настройки Core и подтвердить изменение. В начальном YAML
сохраняются стандартные HTTP-параметры: пробная конфигурация при первом
запуске иначе откатывается через пять минут с перезапуском Core.

Туннель включается после создания владельца. При обрыве приложение повторяет
подключение с задержкой от 5 до 60 секунд и проверяет host key. Выключение
внешнего доступа в настройках применяется при следующем запуске службы.
SIM даёт альтернативный интернет; доступность домашних устройств при потере
Wi-Fi проверяется отдельно.

## Резервные копии и обновление

Остановите сервер и дождитесь завершения остановки. «Сохранить резервную
копию» записывает выбранный пользователем файл `.habak`: tar.gz конфигурации
зашифрован AES-256-GCM; ключ выводится из пароля через PBKDF2-HMAC-SHA256 с
210 000 итерациями и случайной солью. Пароль не сохраняется. Копия содержит
аккаунты и ключи интеграций, поэтому храните её отдельно от публичных файлов.

Для восстановления выберите файл и введите пароль. Проверка GCM завершается
до распаковки и замены конфигурации. Старый каталог сохраняется как
`config-before-restore-TIMESTAMP`; повреждённая копия не заменяет рабочие данные.

Перед обновлением окружения сохраните копию. Новое окружение распаковывается
отдельно и заменяет текущее только после проверки подписи и архива. Каталог
`config/` не перезаписывается. Откат runtime не отменяет миграции базы Core:
для такого отката нужна соответствующая резервная копия.

Удаление APK средствами Android удаляет приватные данные приложения.

## Приёмка на Huawei

- Штатный интерфейс и наши панели доступны внутри APK и через браузер.
- OpenCode отвечает через настроенного провайдера и изменяет тестовую сущность
  через `habab-ha`. Ключ провайдера вводится владельцем в разделе AI.
- Проверены права администратора, история чата и сохранение данных после
  перезапуска. Проверка синтаксиса или `--version` OpenCode этого не доказывает.
- LAN и HTTPS работают, WebSocket передаёт состояния и команды.
- После обрыва сети и падения Core/туннеля работа восстанавливается. После
  пяти подряд неудачных запусков Core останавливается с диагностикой.
- После перезагрузки и первой разблокировки Android служба запускается снова,
  если пользователь не отключил сервер. После force-stop приложение нужно
  открыть вручную.
- Пройдены восстановление резервной копии и 48 часов работы с выключенным
  экраном с проверкой памяти, диска, батареи и нагрева.

Android, EMUI и состояние аккумулятора могут ограничить непрерывную работу.
Системный Bluetooth, USB-координаторы и HAOS/Supervisor в эту APK не входят.
Голос и OAuth-переходы требуют отдельной проверки в Android WebView.

## Лицензии

Происхождение компонентов описано в [NOTICE.md](NOTICE.md). Лицензии native
пакетов входят в assets APK. При распространении native бинарников сохраняйте
исходники соответствующих версий и изменений упаковки; `prepare_native.py`
содержит применяемые изменения, `native-packages.json` фиксирует пакеты.
