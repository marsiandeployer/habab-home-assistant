# Сессии поддержки Habab Home

`support_tunnel.bat` открывает временный обратный SSH-туннель от компьютера
владельца к relay-серверу. Он передаёт только локальный веб-порт Home Assistant.
Команды помощника выполняются внутри контейнера Home Assistant после входа
администратора. Windows shell, Docker API и диски компьютера через туннель
недоступны.

## Действия владельца

1. Запустите Home Assistant, затем `support_tunnel.bat`.
2. Передайте поддержке показанную строку `HABAB1:…`. Это публичный ключ,
   идентификатор сессии и срок доступа; приватный SSH-ключ остаётся на компьютере.
3. Дождитесь подтверждения поддержки и нажмите Enter. Успешное соединение
   показывает `READY: Home Assistant` после проверки native WebSocket API.
4. Закройте окно, когда настройка закончена. Сервер также отключит сессию по
   таймеру: по умолчанию через 60 минут после одобрения, максимум через 120 минут.

Для доступа к Home Assistant нужен отдельный native-вход. Туннель не отменяет
пароль и не создаёт администратора.

## Действия оператора

На relay нужен системный Python 3 с `websocket-client`, OpenSSH Server и systemd.
После установки SSH relay администратором (`python3 relay.py install`) и
получения запроса от владельца:

```sh
python3 relay.py authorize --request 'HABAB1:…'
```

Не одобряйте коды из посторонних источников. Сообщите владельцу, что можно
нажать Enter. После `READY` прочитайте
`/var/lib/habab-support/<session>/connection.json`: в нём указаны адрес
на loopback сервера и время отключения. Проверьте native-вход перед изменением
настроек. Не включайте эти файлы, токены или настройки владельца в отчёты и Git.

Досрочно закрыть конкретную сессию:

```sh
python3 relay.py revoke --session '<32-hex-session>'
```

Для каждой сессии создаётся отдельный системный пользователь с временным
Ed25519-ключом, одним разрешённым loopback-портом и принудительной проверкой HA.
Shell, TTY, локальные SSH-forward и forwarding агента запрещены. Systemd cutoff
удаляет разрешение и останавливает процессы этой сессии, включая клиент `ssh -N`.
Установщик не меняет правила входа root и других пользователей.

Публичный ключ SSH relay закреплён в `distribution/support-relay.json`. При его
плановой смене нужно выпустить новый Windows-пакет. Не отключайте проверку ключа
в клиенте.

## Телеметрия

Сборщик принимает только категории, выбранные владельцем в разделе AI. По
умолчанию все выключены. Адрес: `https://habab-demo.wpmix.net/api/ha-telemetry`.
Встроенная аналитика Home Assistant использует собственное согласие и адрес.

Категории: версии системы; домены интеграций и количества моделей устройств;
количества устройств/сущностей/автоматизаций/пользователей; метаданные исключений
без текста ошибки, строк кода и локальных переменных. Отчёты не содержат ключей,
переписки, состояний сущностей, имён, IP или MAC. Как при любом HTTPS-соединении,
сервер получает сетевой адрес клиента, но приложение не сохраняет его в таблицах
телеметрии; access log этого endpoint отключён на обоих nginx.

Случайный ID установки преобразуется на сервере в HMAC. Это псевдонимные данные,
а не гарантия невозможности определить установку по совокупности характеристик.
Передача основных метрик — при включении, запуске и затем раз в сутки; диагностика
ограничена 20 событиями в день. Отключение категории удаляет её сохранённые данные
при успешной доставке выбора. Полное отключение отправляет запрос удаления.
При сетевой ошибке выбор сохранён локально, но серверное удаление не подтверждено:
повторите сохранение после восстановления связи.

Таблицы создаются из `deploy/telemetry.sql`; срок хранения — 60 дней. Очистка
запускается каждый час через `deploy/ecosystem.telemetry.config.cjs` (PM2).
Публичные сообщения не подтверждают подлинность установки и не используются
для расчётов или авторизации.
