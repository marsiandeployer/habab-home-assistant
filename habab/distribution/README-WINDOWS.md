# Запуск на Windows

Инструкция для Git-checkout относится к исходному кандидату Habab Home 0.3.6
на Home Assistant Core 2026.10.2 с frontend `20260930.4+habab.9`. Публичный
`start-home-assistant.bat` скачивает пакет основного загрузчика 0.3.1. Для
проверки кандидата используйте отдельный [preview-загрузчик 0.3.6](https://habab-demo.wpmix.net/downloads/start-home-assistant-preview-0.3.6-1a844fb6f7a3.bat)
из коммита исходников `3bdc03b6d13f41d142550703e698591bf032563d`. Публичные
[метаданные пакета](https://habab-demo.wpmix.net/downloads/windows-preview-0.3.6-1a844fb6f7a3.json)
указывают ZIP `habab-home-windows-1a844fb6f7a3.zip` размером 290827 байт и
SHA-256 `1a844fb6f7a30e16925fd3aa05ff20c0653cf45caf55def36530cdd3a2e746f7`.
Это предварительный пакет; физическая установка этого preview на Windows не
запускалась, а основной загрузчик по-прежнему выдаёт 0.3.1.
Для новой Git-установки из корня checkout запустите отслеживаемый
`habab\distribution\start-windows.bat`; двойной щелчок тоже подходит. Для
обновления сначала выполните `git pull`. Батник пересобирает локальный Docker-
образ с закреплённым frontend `20260930.4+habab.9` и повторно использует том
`config`. Сохраните рядом остальные файлы `distribution`; не удаляйте том и не
выполняйте `docker compose down -v`, если нужно сохранить Home Assistant.

Отдельный загрузчик `start-home-assistant.bat` доступен на странице загрузки. Запустите его двойным щелчком. Батник скачает проверенный по SHA-256 пакет в `%LOCALAPPDATA%\HababHome` и запустит установку.

Если Docker Desktop отсутствует, скрипт запускает установку через winget или скачивает официальный установщик Docker и проверяет его цифровую подпись. Следуйте окнам установщика и Docker Desktop. Если нужен WSL 2, появится запрос прав администратора. После требуемой перезагрузки Windows запустите батник ещё раз. Виртуализация должна быть включена в BIOS/UEFI.

При стандартном порте 8123 обычный BAT один раз предлагает подготовить адрес
`homeassistant.local` для возможного входа Xiaomi. Windows отдельно спросит
разрешение на добавление `127.0.0.1 homeassistant.local` в hosts. Это только
подготовка адреса: она не устанавливает Xiaomi, не открывает её форму и не
принимает лицензию. Если отказать в запросе, Home Assistant всё равно запустится;
позже адрес callback можно передать через защищённую форму карточки Xiaomi. Уже
существующую запись для `homeassistant.local` на другой IP скрипт не меняет.

OpenCode отдельно в Windows устанавливать не нужно. Скрипт скачивает закреплённый Linux musl-бинарник 1.14.21 из npm, проверяет SHA-512 архива и помещает программу в Docker volume. Контейнер Home Assistant получает этот том только для чтения. Windows-диски, домашняя папка, ключи других программ и Docker socket в Home Assistant не передаются.

После первого запуска откроется `http://127.0.0.1:8123`:

1. Создайте владельца Home Assistant.
2. В разделе **AI** выберите DeepSeek, получите свой ключ в кабинете провайдера и сохраните его. Ключей в пакете нет.
3. После входа один чат администратора откроется на любой странице. На компьютере он занимает панель справа. На телефоне дашборд остаётся сверху, чат появляется снизу; сверните чат, чтобы вернуться к дашборду, или раскройте его на весь экран.
4. Попросите: «Проверь доступ к настройкам Home Assistant и покажи подключённые интеграции».

На странице загрузки доступны три BAT: обычный `start-home-assistant.bat`, отдельный
`start-xiaomi-home.bat` и `support_tunnel.bat`. Они используют одну папку
`%LOCALAPPDATA%\HababHome` и один Docker-проект с тем же томом настроек; повторный
запуск или другой BAT не сбрасывает аккаунт Home Assistant.

Веб-помощник может выполнять команды от root внутри контейнера, смотреть устройства и состояния, вызывать штатные сервисы и запускать подключение интеграций. Карточки настройки используют native `step-flow-form` Home Assistant с его переводами и проверками. Модель получает только имена, типы и обязательность полей; варианты, подписи, defaults, URL и пользовательский ввод остаются за защищённой границей формы. Действия веб-помощника выполняются с правами вошедшего администратора. Для пароля, OAuth или действия на устройстве владелец продолжает настройку в HA. Telegram направляет такие шаги в веб-интерфейс.

Настройки и ключи остаются в локальном Docker volume и переживают повторный запуск. Удаление папки с батником не удаляет настройки HA. Не используйте `docker compose down -v`, если хотите их сохранить.

## Telegram

Раздел **Telegram** в левом меню доступен только администратору.

1. Создайте отдельного бота через `@BotFather`, вставьте токен в защищённое поле и нажмите «Подключить бота». Интеграция сохраняет токен в записи HA; не отправляйте его сообщением помощнику.
2. Нажмите «Получить ссылку для привязки» и откройте одноразовую ссылку в личном чате с ботом. Это отдельный доступ владельца; он продолжит работать, даже если отключить домашнюю группу.
3. Создайте группу «Моя дача» или «Моя квартира», добавьте бота и только доверенных людей. В разделе Telegram нажмите «Создать ссылку для группы», откройте одноразовую ссылку `startgroup` и выберите созданную группу. Назначьте бота администратором для проверки членства.

После подключения участники начинают личный чат с ботом кнопкой «Запустить». Бот проверяет членство в группе при каждом личном запросе; после выхода участника его следующий запрос отклоняется. Сообщения в самой группе бот не обрабатывает. Неизвестному личному чату бот подскажет, как получить доступ. «Отозвать доступ группы» сохраняет привязку владельца; отключение бота удаляет токен и обе привязки. Для OAuth, пароля, кода подтверждения или карточки установки откройте веб-чат HA; не отправляйте секреты боту.

Веб и Telegram используют общий `AssistantService` и OpenCode runtime, сохраняя раздельные истории и контексты. Нативный Assist использует ограниченный HA adapter без доступа к root/OpenCode. Проверка этого кандидата на физическом Windows и личного запроса второго участника отдельно не выполнялась.

## Если запуск остановился

Окно остаётся открытым и показывает причину. Частые причины: Docker Desktop ещё загружается, не принято его соглашение, Windows требует перезагрузки, отключена виртуализация или занят порт 8123. Скрипт не перезагружает компьютер автоматически.

Для другого порта перед запуском в `cmd`:

```bat
set HABAB_HOME_PORT=8133
start-home-assistant.bat
```

### Ошибка ответа встроенного помощника

В ранней Windows-установке 0.2.0 запрос через OpenCode завершился
`model_error`. Позднее на установленной версии 0.3.0 помощник ответил на запрос
без этой ошибки; ответ совпал с реестром Home Assistant: три служебных устройства,
без пылесоса. [Отчёт проверки](../qa/cross-channel-setup/windows-assistant.json).
Кандидат 0.3.6 на физическом Windows ещё не проверен.

Для текущей диагностики запустите `diagnose-assistant.bat`
(`habab\distribution\diagnose-assistant.bat` в Git-checkout). Он не пересобирает
образ и не отправляет запрос модели.

BAT выполняет только локальный read-only запрос к базе ошибок OpenCode внутри
существующего контейнера. Он выводит JSON с типом и HTTP-статусом последних
ошибок и техническими признаками. Тексты переписки, ключи, токены и сырые ответы
провайдера в отчёт не входят. BAT не вызывает модель, не меняет конфигурацию и
не перезапускает HA. Передайте полученный JSON поддержке.

### Xiaomi Home внутри Home Assistant

После обычного запуска откройте иконку чата в Home Assistant и напишите:
«Подключи Xiaomi Home в России».

Помощник откроет карточку подключения в этом же окне. Подтвердите условия
личного использования, нажмите «Установить интеграцию», затем
«Перезапустить и продолжить». Home Assistant перезапустится с теми же настройками.
Выберите регион, подготовьте вход и подтвердите его на официальном сайте Xiaomi.
Пароль и код подтверждения вводятся на сайте Xiaomi, а не сообщениями чата.

Если после входа Windows не открывает `homeassistant.local`, вернитесь в карточку
и раскройте «После входа страница не открылась?». Вставьте туда полный адрес из
адресной строки этой страницы. Адрес обрабатывается только Home Assistant и
не отправляется AI-модели. При стандартном порте callback-адрес обычно готовит
обычный BAT; на другом порте карточка остаётся доступна, но callback Xiaomi
зарегистрирован для 8123.

После подключения карточка показывает количество устройств и предлагает
«Проверить с помощником». Старая `xiaomi_miio` с формой логина и пароля — отдельная
интеграция. Для этого сценария используется официальная `xiaomi_home`.

Код Xiaomi не входит в пакет Habab. Карточка скачивает закреплённую v0.5.0 с
проверкой SHA-256; действуют условия личного некоммерческого использования
[лицензии XiaoMi](https://github.com/XiaoMi/ha_xiaomi_home/blob/75b3acb6325a3a8d295688b13904737d6738a6a5/LICENSE.md).

### Дополнительный вариант: запуск отдельным BAT

`start-xiaomi-home.bat` сохранён для прямого открытия нативной интеграции.
Он устанавливает тот же компонент и открывает его форму в Home Assistant. Обычный
BAT уже готовит callback-адрес Windows при стандартном порте, поэтому отдельный
BAT нужен только тем, кто явно выбирает нативное подключение.

Официальный OAuth callback зарегистрирован для `homeassistant.local:8123`.
Поэтому этот режим требует порт 8123. Обычный BAT при первом запуске отдельно
просит подтверждение Windows UAC, чтобы **добавить** в системный hosts-файл одну запись
`127.0.0.1 homeassistant.local`. Существующие записи и остальные параметры
Windows не меняются; если это имя уже сопоставлено с другим адресом, запуск
остановится без правки файла. Войдите в Xiaomi в официальном окне OAuth, не
передавая пароль помощнику.

BAT открывает добавление официальной интеграции (`xiaomi_home`). Если сначала
потребовалось создать аккаунт Home Assistant, после регистрации откройте
`http://127.0.0.1:8123/config/integrations/dashboard/add?domain=xiaomi_home`.
Выберите Россию и завершите вход Xiaomi, включая код из почты, если он запрошен.
Старая интеграция `xiaomi_miio` с вводом пароля — отдельное подключение.

В режиме Xiaomi BAT пересоздаёт контейнер Home Assistant, чтобы он подхватил
установленную интеграцию. Аккаунт и настройки сохраняются в том же Docker-томе.

### Временная сессия поддержки

Откройте `support_tunnel.bat` после запуска Home Assistant. Он покажет публичный
запрос с временным SSH-ключом. Передайте его поддержке только по своему желанию;
туннель не подключится, пока владелец не подтвердит подготовленный запрос и не
нажмёт Enter. Доступ ограничен веб-интерфейсом Home Assistant на локальном порту:
Windows-командная оболочка и файлы Windows не передаются. Для самого Home
Assistant по-прежнему нужны личная учётная запись и вход администратора. Закройте
окно для отключения. Установка SSH использует отдельное подтверждение Windows UAC.

В разделе AI есть отдельная **выключенная по умолчанию** настройка телеметрии
Habab. Данные отправляются на сервер Habab только после явного выбора категорий;
это не меняет встроенное согласие Home Assistant.

Остановка из `%LOCALAPPDATA%\HababHome`:

```bat
docker compose --env-file .env.opencode-windows -p habab-home-windows -f compose.windows.yaml stop
```

Повторный запуск того же батника сохраняет том настроек. Пакет использует отдельное имя Compose-проекта `habab-home-windows`.

## Bluetooth на Windows

Встроенный Bluetooth Windows не передаётся в Linux-контейнер Docker Desktop
автоматически. Отсутствие `/sys/class/bluetooth`, сокета
`/run/dbus/system_bus_socket` и HCI подтверждает, что в этом контейнере нет
доступного локального Bluetooth-пути. Установка `bluetoothctl` и root-права
сами по себе адаптер не добавляют.

`compose.bluetooth.yaml` предназначен для Linux-хоста с работающими BlueZ и
D-Bus. Добавление этого override к Windows Compose само по себе не пробрасывает
Bluetooth Windows. Его не нужно включать как универсальное исправление.

Для BLE-устройств Home Assistant поддерживает сетевой ESPHome Bluetooth proxy:

1. Подключите совместимый ESP32 с proxy-прошивкой к домашней сети. Готовые варианты
   и web-установщик доступны на [официальной странице ESPHome](https://esphome.io/projects/).
2. В Home Assistant откройте **Настройки → Устройства и службы → Добавить интеграцию → ESPHome**.
   При отсутствии автоматического обнаружения укажите IP proxy. Ключ шифрования,
   если он настроен, вводите в защищённую форму интеграции.
3. Проверьте появление удалённого сканера в **Настройки → Подключения → Bluetooth**
   и подключайте найденные устройства через подходящие интеграции.

Proxy поддерживает BLE, а не Bluetooth Classic. Совместимость конкретного
устройства проверяется отдельно. Этот аппаратный путь в нашей Windows-проверке
ещё не выполнен. Подробности: [Home Assistant Bluetooth](https://www.home-assistant.io/integrations/bluetooth/)
и [ESPHome Bluetooth Proxy](https://esphome.io/components/bluetooth_proxy/).

USB/IP в WSL — отдельная настройка хоста, описанная
[Microsoft](https://learn.microsoft.com/en-us/windows/wsl/connect-usb). Подключение
USB к WSL ещё не доказывает доступность адаптера, драйвера BlueZ и D-Bus именно
контейнеру HA. Для конкретного Windows-адаптера этот способ у нас не проверен.

Для подключения уже добавленного в приложение пылесоса через **Xiaomi Home**
сначала используйте вход в Xiaomi и импорт устройства; локальный Bluetooth HA
для этого облачного пути не требуется. Настройка callback-адреса описана выше.

Исходные требования: [Docker Desktop для Windows](https://docs.docker.com/desktop/setup/install/windows-install/), [OpenCode](https://opencode.ai/docs/). Скрипт использует штатные окна установки и не меняет глобальную Execution Policy PowerShell.
