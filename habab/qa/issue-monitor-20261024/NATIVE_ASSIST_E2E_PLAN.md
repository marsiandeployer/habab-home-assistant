# Native Assist E2E runner plan

`native-assist-e2e.cjs` is a source-only runner for the authenticated Home Assistant `conversation/process` API. It selects the configured Habab native conversation entity through `habab_home/providers/list` and `conversation/agent/list`; it never calls the setup-agent `habab_home/agent/run` API or inspects/changes its sessions.

The live path requires both `--run-live` and a root-issued `--execution-window-id`, plus fresh runtime image/source attestation. That window is the operator's exclusive-idle confirmation: Home Assistant Core does not expose the selected conversation entity's request lock through an admin read API, so the runner cannot independently prove no other native conversation turn is in flight. Unknown or ambiguous selected agents and mismatched runtime identity fail before fixture creation.

The runner creates one uniquely named `input_boolean`, snapshots that entity's exact `conversation` registry options, exposes it only to the native `conversation` assistant, and verifies a read and an action with service-event actor context plus independent REST state reads. It then hides the same fixture and asks for the exact entity ID. The hidden case only counts as ACL evidence when the actual native intent tool log shows that exact target and Core returns an exposure denial; no call/readback alone is insufficient. Raw prompts, replies, entity IDs, user ID, service events, and Core chat logs remain in a mode-0600 trace beside the private auth file. The checked-in JSON report contains only sanitized verdicts and evidence flags and remains `PASS_PENDING_MANUAL_REVIEW` until a person checks the private answers.

Cleanup runs over the same authenticated HA connection. It restores the exact prior per-entity `conversation` option value (including absence), verifies it, deletes only the helper ID created by this run, and verifies helper, registry entity, and state removal. If a conversation turn times out and may still be running, cleanup retains the fixture and marks failure so a late model tool call cannot target a deleted helper. No provider selection, default exposure, existing integration, physical device, or durable setup-agent history is changed.

This preparation was not run against a live HA runtime. `--run-live` must remain blocked until root reviews the source, confirms a fresh image/source identity and exclusive execution window, and explicitly authorizes that window.
