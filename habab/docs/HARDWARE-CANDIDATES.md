# Кандидаты на аппаратную коробку Habab Home

Статус: подбор по спецификациям; физическая приёмка не проводилась. Issue [#6](https://github.com/marsiandeployer/habab-home-assistant/issues/6) требует 8 ГБ RAM, Wi-Fi, отдельный Zigbee-координатор, проверку Docker/ARM64 и измерения нагрузки. Покупка оборудования не входит в этот документ.

## Рекомендация для первого devkit

Первым devkit выбрать **Raspberry Pi 5, 8 ГБ**. Это конкретная 64-битная ARM-плата с Wi-Fi на борту, USB 3 и официальной документацией по установке Home Assistant Container; производитель продаёт её через сеть одобренных реселлеров, но наличие в регионе отдельно не проверялось. ARM64 сборка Habab имеет отдельный candidate job. Для комплекта взять microSD A2 64 ГБ для ОС, внешний SSD 256 ГБ с USB 3 корпусом, официальный USB-C БП 27 Вт (5 В/5 А) и Active Cooler либо корпус Pi 5 с вентилятором. Такая комплектация позволяет проверить именно ARM64 на физической плате; её скорость для Core, Chromium и OpenCode пока не измерялась.

В ограниченном поиске по официальным страницам MINISFORUM карточки S100 8/256 и UN100P 16/256 либо 16/512 были помечены как отсутствующие на складе. Это не основание рекомендовать их к закупке. N100 остаётся baseline по архитектуре: минимум 8 ГБ RAM, x86-64, SSD от 256 ГБ и встроенный Wi-Fi либо явно совместимый модуль. В этом документе нет подтверждённо доступной модели N100.

Основание выбора: принятый локальный образ уже собран и проверен на amd64 ([проверенный объём](../distribution/README.md#проверенный-объём-и-ограничения)); для amd64 и arm64 предусмотрены отдельные сборки кандидата ([workflow](RELEASE-CANDIDATE.md)), но артефакт workflow не подтверждает запуск на физической плате. Установщик OpenCode содержит отдельные закреплённые пакеты amd64 и arm64 ([манифест](../distribution/opencode-release.json)). Raspberry Pi 5 сочетает конкретные характеристики платы, встроенный Wi-Fi и описанный Home Assistant путь для Docker. Это не обещание производительности уровня Core i5: в Issue #6 нет модели i5 или согласованного теста сравнения. Производительность и задержки измерить на выбранном экземпляре.

## Общая радио-комплектация

- **Zigbee:** Home Assistant Connect ZBT-2, один координатор на одну Zigbee-сеть. Для нового ZHA это рекомендуемое HA-устройство; производитель также описывает использование с Zigbee2MQTT. В каждый момент назначить координатор только одному Zigbee-стеку: ZHA **или** Zigbee2MQTT. Если выбран Zigbee2MQTT, дать доступ к USB-устройству только его контейнеру.
- Подключать ZBT-2 штатным кабелем USB-C/USB-A длиной 1,5 м из комплекта; вынести антенну от корпуса, USB 3 SSD и Wi-Fi-роутера. Передавать стабильный путь устройства (`/dev/serial/by-id/...`), а не меняющийся `/dev/ttyUSB*`.
- ZBT-2 работает либо как Zigbee, либо как Thread, не одновременно. Подключение и сопряжение устройств, доступность сети после перезапуска и выбранный канал остаются пунктами физической приёмки.
- [ZHA: совместимое оборудование и выбор координатора](https://www.home-assistant.io/integrations/zha) · [Connect ZBT-2: характеристики и протоколы](https://www.home-assistant.io/connect/zbt-2/)

## ОС и границы совместимости

Для всех трёх вариантов нужен 64-битный Linux с Docker Engine и Compose v2. Habab Home — Docker Core, а не Home Assistant OS; ОС и обновления хоста остаются ответственностью владельца. Сборка приложения должна пройти для фактической архитектуры. Наличие ARM64-варианта OpenCode в установщике само по себе не подтверждает ARM64-образ Core, доступность всех зависимостей, Wi-Fi-драйвер или работу Zigbee на плате.

Документация проекта фиксирует успешную чистую сборку на Linux, но не физическую приёмку этих устройств. N100 остаётся baseline, но актуальный доступный SKU официальным поиском не подтверждён. Raspberry Pi 5 выбран для первого физического ARM64 испытания; Orange Pi остаётся альтернативой.

Голосовая функция опциональна; нагрузка зависит от выбранного локального или удалённого стека, поэтому измеряется после выбора сценария. N100 и ARM NPU не объявляются эквивалентом i5 или готовым ускорителем голоса. Голосовые задержки не оценивались.

Справка Home Assistant: [Docker Container](https://www.home-assistant.io/installation/raspberrypi-other) · [установка на Linux](https://www.home-assistant.io/installation/).

## Физическая приёмка — ещё не выполнена

- [ ] Записать модель платы/mini PC, ревизию, объём RAM, маркировку накопителя и версию BIOS/UEFI.
- [ ] Поставить актуальную 64-битную ОС; проверить холодную загрузку, перезапуск и восстановление Docker после обесточивания.
- [ ] Собрать и запустить именно проектный Docker-образ для архитектуры устройства; зафиксировать digest и журнал запуска Core 2026.10.2 и OpenCode.
- [ ] Сверить доступное место на накопителе; проверить чтение/запись тома `/config` после перезапуска. Для Pi нагрузочный прогон делать с SSD, не только с microSD.
- [ ] Проверить LAN и Wi-Fi отдельно: адрес, переподключение после потери точки доступа и повторное подключение после перезагрузки.
- [ ] Подключить один ZBT-2, проверить выбранный USB-путь, создать Zigbee-сеть, сопрячь тестовое устройство и проверить восстановление после перезапуска. Не открывать один serial device двум Zigbee-стекам.
- [ ] На штатном охлаждении прогнать Core, браузерный сценарий и обычную нагрузку OpenCode; записать температуру, частоты, RAM/swap, шум и ошибки.
- [ ] При включённом опциональном голосовом сценарии записать число повторов, сеть/провайдера и задержки по этапам; не переносить результаты на другую модель или плату.

До этих проверок аппаратная совместимость, уровень производительности, стабильность Zigbee и голосовые задержки имеют статус **не проверено**.
